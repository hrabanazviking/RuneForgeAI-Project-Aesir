## 0. Protocol (committed first, before either example was built)

This section was committed and push-verified before the example artefacts, the fixtures, or any verification script were written. It states the two examples' exact shapes, the execution each one must undergo (a written-but-unrun example fails this slice by the roadmap's own words), the verdict rules, and what is deferred and why. Everything after §0 is filed under these rules and no others.

### 0.1 Example 1 — chat in a web page, against the server

- **Artefact:** `aesir_engine/docs/janas/j117_example_chat_page.html` — one self-contained HTML document (inline style + inline script, zero external references, no framework), filed in `docs/janas/` because that is this tree's convention for filed example/client artefacts (J-109's `j109_mcp_client.py`, J-116's `j116_adapter_replica.py`, J-114's `j114_cost.mojo` driver all live there; J-099's census found no `examples/` directory anywhere in the tree, and this slice does not invent a second convention). It is a *worked example*: a teaching page an operator can save and open against a running Aesir server, with its contract stated in its own header comment. It is **not** a second served page — J-108's `GET /` document remains the server's page; this example deliberately mirrors that page's client logic (same audited calls, same stream vocabulary) so the two cannot drift in what they send.
- **What it may call (exactly the J-106-audited shape, as J-108 §0.1):** `GET /v1/models`; `POST /v1/chat/completions` with `model` + `messages` + `stream`, plus `stream_options.include_usage` when streaming. Nothing else. Errors are shown verbatim in a status line; transcript text is inserted with `textContent` only (no `innerHTML` anywhere); the design-law numbers of J-108 §0.4 apply (16 px body text, ≥ 44 px controls, labelled fields, status always in words, one accent marking Send only, no ornament).
- **Its execution (the slice's point):** `j117_web_client_check.mjs` (Node, standard library only — Node is present on this VM) extracts the page's **actual `<script>` block** from the filed HTML and runs it headlessly: a minimal DOM stub (the exact element ids the script looks up, `createElement`/`appendChild`/`textContent`, captured click handlers), a `fetch` stub answering from **filed response artefacts** (`j117_web_fixtures.json` — the models list, a streamed SSE transcript carrying a `prefill_progress` event + content chunks + a usage chunk + `[DONE]`, a plain completion body, and a refusal body, each shaped from J-106/J-107's filed shapes and labelled as filed-shape artefacts, never as live captures). The check drives the page's own `loadModels` path and its Send path three ways (streamed, plain, refused) by invoking the captured Send handler, and asserts: the request bodies the page actually built (route, method, `stream` flag, `include_usage` exactly when streaming, the history it sent), the assembled answer text, the history the page kept, and the status words it ended in (progress percent seen, usage counts rendered, refusal shown verbatim). Opening the HTML and admiring it is not a verification and is not claimed as one.
- **What this execution is not:** no live server is started and no browser engine runs (the VM bounds in §0.4). The live leg — the example page open in a real browser against a live serve, ids-first grading — is J-108 §5's recipe step 3, DEFERRED-WITH-REASON and re-cited in §7 for the J-118 gate, exactly as J-108 filed it for this slice.

### 0.2 Example 2 — a program embedding the engine

- **Artefact:** `aesir_engine/docs/janas/j117_example_embed.mojo` (a driver `.mojo` in `docs/janas/`, the J-114 `j114_cost.mojo` precedent) — a worked Mojo program embedding Aesir through the Mojo-native door J-115 §4 graded PROVEN: it imports the `AesirEngine` facade from the `aesir` module, constructs it over a model path given as its argument, and — when a model loads — exercises the answering entries a host chat program needs (`generate_chat` over `ChatMessage` turns, `generate` for a raw prompt, `save_checkpoint`/`load_checkpoint` as the session's position marker). With no argument, or over a path that does not load, it prints the honest fail-closed outcome (the construction raise, caught and reported) and exits without inventing any generation.
- **The reserved five, named on the example's face:** `ingest_document`, `join_swarm_cluster`, `dispatch_swarm_inference`, `speculative_generate`, `generate_tokens_with_grammar` (J-115 §2.4: each raises not-implemented/unavailable on its face). The example **names them in its header as entries it must not pretend to use**, calls none of them, and its verification asserts the naming is present. An example that silently called a reserved entry, or implied it worked, would fail this slice.
- **Its execution, in two tiers (both filed, neither conflated):**
  - **Tier 1 — the facade example's own build.** Its compilation is attempted once on this VM at the lightest target, one process at a time, under §0.4's bounds, and the outcome is filed exactly as it lands (success, or the failure's own words). A compile success is graded as compilation only — it is not a generation claim.
  - **Tier 2 — the embeddable surface, executed.** `j117_embed_check.mojo` (the verification companion, also in `docs/janas/`) imports the library modules the facade itself delegates to — `core/state_vault` (the machinery behind the facade's `save_checkpoint`/`load_checkpoint`), `loader/chat_template` (the `RuneChatTemplate`/`ChatMessage` machinery behind `generate_chat`), `core/session` (the `SessionContext` behind `generate_session`) — and **runs** their answering behaviour with no model: a checkpoint save→load round-trip against a staging file (values compared exactly), a chat formatting over two turns (the formatted prompt asserted), a session context validated. This tier proves, by execution, that the in-process embeddable surface a host links today answers on this VM; it does **not** claim the facade tier ran, and the doc grades the two tiers separately wherever either is cited.
- **The model-bound leg is not part of either tier:** constructing the facade over a real model and generating through it is VM inference (barred by the 5,500 MB gate, §0.4) with no model file available to this slice on the VM (the tree's `model.gguf` is a 24-byte placeholder; J-115 §9 already grades every live leg from the owning slices' proofs). It is DEFERRED-WITH-REASON with its exact recipe in §7, re-cited at the J-118 gate.

### 0.3 Evidence method and verdict rules (pre-registered)

- `j117_inspect.py` re-derives every load-bearing claim from the trees and the filed outputs: both examples' shapes and invariants (the web page's self-containment, audited-calls-only, stream vocabulary, design-law numbers; the embed example's facade import, its answering-entry calls, its reserved-five naming and non-use), both checks' filed outputs (the Node check's assertions, the light driver's run, the facade build attempt's outcome as filed), the deferred set's recipes, and repo hygiene (diff == the expected file set, no README touched, no model file present).
- **Honesty classes:** PROVEN / SIMULATED / MEASURED-INDICATIVE / NOT PROVEN, per the road's law. The Node check's runs are **executions of the page's own script against filed-shape artefacts** — graded PROVEN for the client logic (request building, stream parsing, state keeping) and never as live-server or browser-engine behaviour. The light driver's run is PROVEN for the modules it imports and runs. The facade tier is graded by its filed build outcome alone. No tok/s, latency, or live-generation claim is made anywhere in this slice.
- **A written-but-unrun example fails the slice:** if a check above does not run, its example is filed as NOT PROVEN with the reason, never as done. A check that fails is a defect to fix in scope (the example or the check's own extraction, disposed in the doc), never a number to file quietly.
- **Build rule:** no Aesir engine code changes in this slice. If an example exposes a defect *in Aesir's own terms* in an engine module, it is fixed in scope with tests under the never-leave-a-bug law; a defect in this slice's own artefacts is fixed before any number is filed.
