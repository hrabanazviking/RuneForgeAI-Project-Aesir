## 0. Protocol (committed first, before any code was built)

This section was committed before the manners module, the wiring, or any test existed. It states what the inspection found, the four manners as decision rules, the suggestion and env-typo rules, the write-discipline census rule, and the verdict rule for the slice; everything after §0 is filed under these rules and no others.

### 0.1 What exists, and the exact delta (re-verified first-hand in this tree at the base tip)

- **Interrupt machinery exists and is honest at the reader level.** `cli/interrupts.mojo` blocks SIGINT (and SIGTERM where asked) and delivers it through a signalfd; `read_interruptible_line_result` returns an `InterruptibleLine` that keeps three outcomes **distinct**: `interrupted` (SIGINT arrived while waiting), `eof` (end of input — Ctrl-D / closed stdin), and the line's text. Generation cancellation is real: sessions poll the descriptor through `core/generation_control.mojo` (`cancellation_ready` → finish reason `"cancelled"`), and the chat help already states "Ctrl+C cancels generation".
- **DEFECT (the delta this slice fixes): the main prompt conflates the reader's distinct outcomes.** Both interactive loops in `cli/cuda_chat.mojo` read the prompt through `read_chat_line` → `read_interruptible_line`, the compatibility wrapper whose own docstring states "chat treats interruption and EOF as session end": an interrupted read and an EOF both surface as the empty string, and the loops' `prompt == ""` test then **breaks the session**. So today Ctrl-C at the prompt — with no reply running, nothing to stop — **leaves the chat**, exactly what the roadmap manner forbids ("Ctrl-C stops a reply and nothing else; Ctrl-D leaves"). The compose and editor surfaces already honour the distinction (`cli/chat_compose.mojo`: interrupt discards the draft and stays; EOF leaves) — the main prompt is the odd surface out. A second, smaller conflation of the same family sits after each turn: `if consume_interrupts(interrupt_fd) and session.finish_reason != "cancelled": break` — a Ctrl-C that arrives after a reply has finished (nothing left to stop) also ends the session.
- **Refusal-by-name exists; suggestions are absent.** The CLI dispatch ends `raise Error("unknown command: " + cmd)` (`cli/commands.mojo`); both `chat_control` bodies end `raise Error("Unknown chat command; use /help")` — which does not even name what was typed; the chat option parser raises `"Unknown chat option: " + flag`. A tree-wide scan finds no "did you mean" anywhere in `cli/` (J-099's finding, re-verified).
- **Env-var reading is literal and silent about near misses.** Every `AESIR_*` variable is read by an exact-name `getenv` helper in its owning module (21 names with a literal read call site — §0.4's census). A misspelt name (e.g. `AESIR_CAHCE_HOME`) is simply never read: the setting it meant to carry is silently dropped, with no report at start or anywhere else. Nothing enumerates the process environment at chat start.
- **Write discipline exists by construction but is nowhere stated or graded as a rule.** The engine's file-mutating primitives (`open64`/`open` with write flags, `rename`, `unlink`, `mkdir`) live in a closed set of files across `cli/`, `core/`, `server/`, `loader/` (the §0.5 census set). Their destinations are: the cache home's stores (learned file, saved config, model preferences, quantization tuning), the configured model store (catalogue + downloads of *new* files), user-chosen outputs (transcript `--log`, `/save`, `/export`, the autosave directory, state-vault checkpoints under a chosen directory, the server's key files under their chosen home), and kernel control interfaces (`core/linux_cgroups.mojo`, `core/retrial.mojo` — writes to cgroup/sysfs control files, not file destinations). Model files are opened read-only by construction: `loader/gguf.mojo` opens with `O_RDONLY | O_NONBLOCK | O_CLOEXEC` (flags 526336, commented in place) and maps `PROT_READ`; `core/stream_reader.mojo` preads from a read-only descriptor. No loader or session write targets a model path — but no tested rule says so.

### 0.2 The manners as decision rules (the pure layer)

A new pure module, **`aesir_engine/core/chat_manners.mojo`**, owns the manners as decisions every host surface shares, following the road's established shape (pure logic unit-tested at the lightest target; hosts execute the decisions; no session is faked):

- **M1 — Ctrl-C stops a reply and nothing else.** Two decisions:
  - `classify_prompt_line(interrupted, eof, text)` → `LINE_REPROMPT` when `interrupted` (the partial line is already discarded by the reader; the session re-prompts and nothing else happens); `LINE_LEAVE` when `eof` with empty text (Ctrl-D — §0.3 M2) or when the text is empty (a blank line — the loops' pre-existing stated behaviour, "Blank input/EOF ends the session", **kept unchanged**: it is a stated manner of the existing surface, not one this slice was commissioned to change) or the text is `/bye`; `LINE_SUBMIT_FINAL` when `eof` with text (the final unterminated line is submitted; the next read leaves); `LINE_SUBMIT` otherwise.
  - `post_turn_action(interrupt_pending, finish_reason)` → `POST_TURN_STAY` when no interrupt is pending or the turn finished `"cancelled"` (the interrupt did its one job — stopping that reply — and is spent); `POST_TURN_STAY_NOTED` when an interrupt is pending but the reply already finished on its own (the interrupt had nothing to stop; it is drained, a note is emitted, and the session continues). **An interrupt alone never ends an interactive session.** The from-file prompt mode is explicitly out of this rule's scope (answered-locally, §8): a scripted batch has no session to preserve, and its existing break-on-interrupt stands untouched.
- **M2 — Ctrl-D leaves.** EOF is the only keyboard route out besides the stated blank-line and `/bye` behaviours: `classify_prompt_line` maps bare EOF to `LINE_LEAVE`, and a partial line at EOF is submitted once (`LINE_SUBMIT_FINAL`) before the next read leaves. Compose/editor EOF already leaves; untouched.
- **M3 — the engine writes only where it is told.** `classify_write_destination(path, cache_home, chosen_roots, model_paths)` → `WRITE_REFUSED_MODEL` when the path **is** one of the model files (exact match; checked **first**, so a model file that happens to live under the cache home is still never a write target — M4 outranks M3's cache allowance); `WRITE_ALLOWED_CACHE` when the path is the cache home or under it; `WRITE_ALLOWED_CHOSEN` when the path is, or is under, a root the user chose (the transcript path, a `/save` or `/export` target, the autosave directory, the model store, a checkpoint directory); `WRITE_REFUSED_STRAY` otherwise. Prefix matching is path-segment exact (`/cache2` is not under `/cache`); an empty root never matches. This slice grades the tree against the classifier by the §0.5 census; it does not insert a runtime gate at every write site (recorded in §9 — the classifier is the tested rule, the census is the evidence, and a runtime gate is host work under this contract, exactly as J-104 left its reconciliation's consumption to hosts).
- **M4 — model files are never modified.** The classifier's first rule (above) states it as a decision; the loader evidence states it as construction (read-only open flags + `PROT_READ` mapping, pinned by the inspect); the census (§0.5) confirms no mutating primitive's destination in the tree is a model path.

### 0.3 Suggestions (T06's suggestion half)

- **Rule:** `edit_distance(a, b)` (Levenshtein over bytes; all candidate vocabularies are ASCII) and `suggest_match(typed, candidates)`: the nearest candidate at distance ≤ 2 and < the typed length, first in candidate order on ties; an exact match or an empty typed string suggests nothing (an exact match is not a typo, and a refusal for it has another cause). The refusal text gains `; did you mean '<name>'?` only when a suggestion exists — a suggestion is an addition to refusal-by-name, never a change to what is refused, and a suggested name is never executed.
- **Candidate sets (each pinned by the inspect against its surface):** the CLI's top-level command names (the `dispatch_command` chain + the catalog and preference predicates' names); the chat's slash names (both `chat_control` bodies' branches + the loop-level `/compose`, `/edit`, `/transcript`, `/bye`); the chat option flags (the `run_cuda_chat` parser's `--*` literals).
- **Wiring:** `cli/commands.mojo`'s unknown-command refusal; both `chat_control` bodies' unknown-command refusal (which also gains the typed command's first word, so the refusal names what was refused, as T06's strict-refusal half already requires elsewhere); `run_cuda_chat`'s unknown-option refusal.

### 0.4 Env-typo reporting (T06's env-typo half)

- **Census rule:** the known set is every `AESIR_*` name with a literal env-read call site in `core/`/`cli/`/`server/`/`loader/` (mechanically extracted by the inspect: a literal `("AESIR_…")` argument to an env-read helper — 21 names at the base tip), **plus** the documented-but-unread names whose env equivalents are specified in module docs but whose read plumbing has not landed (`AESIR_EXPERT_CACHE_BYTES`, `AESIR_DENSE_LAYER_CACHE_BYTES`, `AESIR_PREFILL_BATCH` — a user setting one today is silently ignored, which is the same harm the manner guards; the doc records them as documented, §7). File-format magics (`AESIR_SAVED_CONFIG_V1`, `AESIR_LEARNED_PLACEMENT_V1`, …) are **not** env names and are excluded (they end in `_V1`/`_V2` and appear as record headers, never as getenv arguments — the extraction pattern cannot see them).
- **Audit rule:** `audit_env_name(name)` → the known name it most likely meant, or nothing: a present name is reported only when it starts with `AESIR_`, is not itself known, and `suggest_match` finds a near known name (same threshold as §0.3). A present `AESIR_*` name near nothing known is **not** reported (answered-locally, §8: it may be the user's own extension or a future name; the manner reports likely typos, not strangers). Correctly spelt names are never reported.
- **Host:** `env_manner_warnings()` (the module's one impure function, in the tree's pattern of a pure module carrying its disk/env surface) reads `/proc/self/environ`, splits the NUL-separated entries, audits each name, and returns one warning line per near miss, each naming the present name, the likely intended name, and the fact that the present name is never read. `run_cuda_chat` prints the warnings at start (after the interrupt bootstrap, before model choice). Reading an unreadable `/proc/self/environ` yields no warnings and no error (the audit is a manner, not a gate).

### 0.5 The write census (M3/M4 evidence)

The inspect enumerates, mechanically, every file under `aesir_engine/{cli,core,server,loader}` containing a file-mutating primitive (`external_call["open64"]`, `external_call["open"]`, `external_call["rename"]`, `external_call["unlink"]`, `external_call["mkdir"]`, or a Mojo `open(…, "w"/"a")`), and this doc's §3 must classify **every** enumerated file's write destinations under §0.2 M3/M4 (cache home / chosen output / model-store ingest of new files / kernel control interface / read-only — no writes). A file entering or leaving the set without the doc's table changing fails the inspect, so the census cannot silently rot. The classifier's unit tests grade the census rows' shapes (a learned-file path under the cache home; a transcript path as a chosen file; a model path refused even inside the cache home; a stray path refused).

### 0.6 Wiring summary (what changes in existing files)

- `cli/cuda_chat.mojo`: both interactive loops read via the result form (`read_interruptible_line_result` through a new `read_chat_line_result` helper beside `read_chat_line`) and act on `classify_prompt_line` (`LINE_REPROMPT` → re-prompt; `LINE_LEAVE` → break; submit forms → the existing turn flow, with `/compose`/`/edit`/`/transcript` still matched on the submitted text); the post-turn break becomes `post_turn_action` (stay / stay-noted, the note emitted on the transcript); both `chat_control` unknown-command refusals gain the typed word + suggestion; the unknown-option refusal gains a suggestion; `run_cuda_chat` prints `env_manner_warnings()` at start.
- `cli/commands.mojo`: the unknown-command refusal gains a suggestion.
- `cli/interrupts.mojo`: the compatibility wrapper stays for its other callers, but its docstring's claim ("chat treats interruption and EOF as session end") is corrected — it no longer states the chat's behaviour, since the chat now distinguishes; the wrapper is a text-only convenience for callers that do not drive a session.
- No session, loader, store, or server file changes. No behaviour of `/save`, `/load`, `/export`, `/set`, `/save-config`, compose, or editor changes.
