# AESIR 500-Slice Advanced Expansion Roadmap

> **Planning backlog, not a capability declaration.** `CAPABILITY_LEDGER.md` remains the sole present-tense capability authority. Every slice below is proposed work; acceptance is earned only by its recorded evidence.

## Purpose and operating rules

This roadmap decomposes broad AESIR growth into 500 small, dependency-ordered work slices across truth/evidence, memory, compute, format support, model quality, lifecycle, service, retrieval, quantization, CUDA, portability, security, performance, user experience, operations, advanced research and release stewardship. It is based on the current repository backlog and documented architecture, not a promise that every platform, model, or provider can be supported.

The roadmap groups 50 work programs into 17 phases. Each program has ten gates: contract, baseline, interface, implementation, unit evidence, integration evidence, adversarial evidence, independent review, documentation, and release gate. A slice is one program crossed with one gate; the resulting IDs are stable `AES500-NNN`. The gate definitions below specify the minimum evidence expected. A program's domain is its owner. The previous slice is a sequencing dependency; work may be parallelized only when its contract explicitly permits it.

Rules for execution:

- Read the current `TODO.md`, architecture, interfaces and capability entry before starting a slice; historical ‘next’ notes do not override the current frontier.
- Publish a task contract before implementation. Preserve default behavior unless a slice proves and explicitly authorizes a separate opt-in capability.
- Correctness, memory safety, state recovery and independent evidence precede timing, admission or promotion.
- Do not delete existing source, fixtures, model bytes, assets or history without approval for that exact scope.
- Keep fixture, physical hardware, external compatibility, portability and production claims distinct.
- Every completed slice gets its own commit and push; continue into the next slice once its inputs and acceptance gates are available. If hardware, external oracle, review, or CI is unavailable, finish the independent work and record that gate as pending rather than claiming completion.
- A roadmap entry is not permission to bypass repository Git discipline. Use a feature branch and the repository's review/merge protections.

## Current baseline and first slice

At the planning baseline, `ROADMAP_AESIR_SPEED_LEAD.md` names strategy5 cooperative control recovery as the current native fixture frontier. Strategy5 has narrowly documented model, causal-generation and sealed replay evidence; control recovery and owned tracing remain open. The normal service retains its admitted original path. First execution is `AES500-001`, strategy5 control contract. The next implementation work order is the already-scoped strategy5 cooperative timeout/cancel/reset/recovery gate, followed by strategy5 owned tracing, then runtime breadth. This work makes no speed claim and does not promote strategy5 to normal service.

The capability ledger's current count and evidence commands are a snapshot. Re-read the ledger and exact evidence before each capability decision.

## Standard gates

| Gate | Required acceptance evidence |
|---|---|
| contract | Publish the exact owner, inputs, outputs, invariants, exclusions and acceptance commands; reviewer confirms the slice is independently scoped. |
| baseline | Capture a reproducible pre-change baseline with source/tool/model identities and preserve raw failures; baseline is rerunnable from a clean task directory. |
| interface | Make the owning interface explicit and validate accepted/rejected inputs without changing unrelated public behavior. |
| implementation | Implement only the named behavior; compile or execute the owning path and show every failure remains explicit. |
| unit-evidence | Add focused executable evidence for normal, boundary and malformed cases; all assertions are tied to the named contract. |
| integration-evidence | Exercise the adjacent owning domains end to end with exact state/output comparisons and no orphan wiring. |
| adversarial-evidence | Run hostile bounds, interruption, mutation, resource and cleanup cases relevant to the slice; reject unsafe cases before mutation. |
| independent-review | Have the Auditor reconcile source, evidence and capability wording; no unsubstantiated maturity or performance claim remains. |
| documentation | Synchronize task, interface, ledger, TODO and devlog owners; links resolve and evidence boundaries are stated. |
| release-gate | Rebuild from the pinned toolchain, run declared suites, inspect the final diff, commit and push this slice, then verify the exact remote revision and hosted CI. |

## Program sequencing notes

- The first four phases establish evidence integrity, memory safety, numerical contracts and trustworthy input formats before broad runtime claims.
- Tokenization, generation, persistence and service work depend on their respective format and state contracts; protocol work cannot imply broad compatibility from a local fixture.
- Retrieval, quantization breadth and accelerator expansion are earned per independently validated model/backend, not by adding routing types or metadata labels.
- Advanced agent and multimodal tracks remain research until real end-to-end inputs, independent quality criteria, safety boundaries and operational behavior pass.
- The 500 items are bounded backlog units, not a completion forecast. New defects enter through evidence-backed contracts and may revise ordering without erasing history.
