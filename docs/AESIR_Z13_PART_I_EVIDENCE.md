## Go / No-Go - GPU kernel work

Verdict: GO - conditional, for GPU kernel work via the proven FFI roads (Vulkan SPIR-V first, HIP/HIPRTC second). NO-GO for NPU kernel work and for any Mojo-native GPU kernel claim until A-029 decides.

Grounds (all device-execution evidence, not visibility):
- A real GPU kernel has already run and been oracle-checked on this machine through both roads: Vulkan compute dispatch byte-exact at 8 sizes (A-015) and HIPRTC kernels checksum/byte-exact in managed memory (A-008, A-019, A-021).
- The memory architecture those kernels need is proven, not designed: zero-copy with copy counters at 0 (A-019), weights 99.52 percent single-residency (A-020), KV shared both directions (A-021), ownership law enforced (A-022), budget governor measured (A-023), copy-path verdict filed (A-025).
- The safety rails for kernel work exist: thermal/power sensing feeding later throttling (A-018), placement policy with logged fall-through (A-017), and a closing suite baseline of 345/1/2 of 348 with the sole failure pre-existing and roaded.

Conditions (roadmap order already enforces them):
1. Wave 4 hygiene first: A-028 (zero NVIDIA flags) and A-029 (Mojo GPU target investigation) precede Part III; the kernel strategy - FFI SPIR-V/HIP vs Mojo-native vs hybrid - is chosen from A-029 compiled probes, not preference.
2. Every future kernel claim keeps Part I discipline: device-execution evidence + byte-exact CPU-oracle comparison (raw-oracle discipline); presence is never execution.
3. NPU kernel work stays NO-GO until the xclbin toolchain exists (A-092 VTD archive step first, plus the A-007 memlock decision).
