# Bug 0023: Model Store Is Process-Local and Commands Have No Durable State

## Severity

P1 core CLI capability blocker and P2 integrity/recovery blocker.

## Owning Domains

- `aesir_engine/cli/manifest.mojo` — catalog and manifest ownership
- `aesir_engine/cli/commands.mojo` — user-facing catalog mutations
- `aesir_engine/cli/modelfile.mojo` — creation input contract
- `aesir_engine/config.mojo` — caller-selected store location

## Symptom

`RuneModelStore` starts empty on every construction, stores manifests only in a
`Dict`, and serializes only to caller-owned text. `dispatch_command()` creates a
fresh store for every invocation and rejects `list`, `show`, `create`, `cp`,
`rm`, and `ps`. No catalog, model blob, or mutation survives process restart.

The current manifest fingerprint covers Modelfile text with FNV-1a. It is an
identity hint, not a cryptographic digest of model bytes. Size, quantization,
dimensions, and modification data remain unknown unless a future loader
measures them.

## Violated Invariants

- A storage command must mutate durable state or fail; process-local mutation is
  not model management.
- Durable writes must be atomic and recoverable after interruption.
- Catalog records must be versioned, bounded, strictly parsed, and protected
  from path traversal and duplicate identity ambiguity.
- Integrity digests and byte sizes must come from the stored bytes.
- Restart, corruption, permission, rollback, in-use, and concurrent mutation
  behavior must be executable evidence.

## Desired End State

1. Add a caller-configurable, relative-by-default store root.
2. Define a versioned catalog and content-addressed blob layout.
3. Read an absent store as an empty catalog without seeded data.
4. Validate names/tags and reject traversal, separators, controls, duplicates,
   malformed records, unsupported versions, and inconsistent blob references.
5. Compute a cryptographic digest and exact size from source model bytes.
6. Stage writes to a same-directory temporary file, flush/sync, atomically
   rename, and preserve the last valid catalog on failure.
7. Implement restart-safe create/copy/remove/update with explicit in-use and
   not-found behavior.
8. Connect `list`, `show`, `create`, `cp`, and `rm`; keep `ps`/`stop` separate
   until a real live-session registry exists.

## Boundaries

- No model weights or generated catalog are committed to the repository.
- No fictional metadata is inferred from a Modelfile.
- Network pull/push and Hugging Face transport remain separate capabilities.
- The first implementation target is the configured Linux build. Portability
  status remains unchanged until a platform-safe filesystem abstraction and
  platform CI exist.
- Existing tracked generated artifacts are not removed without separate human
  approval.

## Verification Plan

- Caller-owned temporary store with empty-start, create, reload, copy, remove,
  rollback, invalid-name, corruption, and missing-blob tests.
- Exact digest/size comparison against a small generated byte fixture.
- Built-CLI multi-process sequence proving state survives separate invocations.
- Master suite, native build, deliberate negative control, consistency check,
  artifact scan, `git diff --check`, and hosted CI.

## Test-Cleanup Approval

On August 29, 2026, Volmarr approved deletion of temporary files and
directories created by the model-store tests only. This authorization is
strictly limited to test-owned paths created during the current test run. It
does not authorize deletion of tracked files, pre-existing files or
directories, user data, model weights, or any production store contents.

## Partial Repair — Durable Catalog Slice

The first implementation slice adds a caller-owned relative Linux store root,
an absent-store-as-empty rule, strict model identity validation, and a bounded
versioned catalog codec whose manifest payloads are hex encoded so caller text
cannot collide with record delimiters. Mutations reload under an exclusive
directory lock, stage in the destination directory, sync the staged file,
atomically rename it, sync the store directory, and publish in-memory state
only after the write path succeeds.

`E-MASTER` case `cli.manifest_store_restart` proves empty start, traversal and
catalog-version rejection, delimiter-safe Modelfile content, and durable
create/copy/remove behavior across reconstructed store instances. The test
deletes only its newly created `.aesir-test-model-store-<pid>` catalog and
directory under the approval above.

The built CLI now wires `create`, `list`/`ls`, `show`, `cp`, and `rm`/`delete`
to this catalog. `scripts/test_native_model_store.py` runs each operation in a
separate process and proves restart state, machine-readable output, rollback,
native-filesystem modes, and final-symlink rejection. Catalog/config reads are
bounded and retry interrupted syscalls.

The bug remains open for content-addressed model blobs, SHA-256 over source
bytes, measured size/metadata, injected I/O faults, missing-blob handling,
process-concurrency stress, and the separate live-session registry needed by
`ps` and `stop`.

## Configuration Slice Contract

Before command wiring, `AesirConfig` will own a `model_store_path` value with
the relative default `.aesir/models`. The tracked JSON schema will expose it in
a `storage` object, normalized configuration output will preserve it, and the
parser will reject empty, absolute, backslash-separated, traversal-shaped, or
otherwise unsafe path components. `DurableModelStore` will reuse that single
validator so configuration and filesystem enforcement cannot drift.

Implemented in the configuration slice: the tracked schema, default,
normalized output, parser validation, durable-store delegation, focused
unsafe-path checks, and production `.aesir/` ignore boundary now agree.
