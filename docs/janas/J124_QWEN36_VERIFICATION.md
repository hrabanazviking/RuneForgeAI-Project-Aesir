### 0.4 The layout (public record + Aesir's filed records, with its arithmetic stated as a prediction)

From the public model cards / Qwen team descriptions (Qwen3.6-35B-A3B, sharing its architecture and model type with Qwen3.5-MoE per the public record): 40 layers in the repeating pattern 3 × (Gated DeltaNet → MoE) then 1 × (Gated Attention → MoE) — i.e. every `full_attention_interval`-th layer (interval 4, 1-based) is an attention layer, the rest are Gated-DeltaNet SSM layers (30 SSM / 10 attention). Gated Attention: 16 Q heads, 2 KV heads, head dim 256 (Q width 4096, KV width 512 at the real geometry), partial RoPE (64 of 256 dims). Gated DeltaNet: SSM inner 4096 class geometry (32 value heads × 128). MoE on every block: 256 routed experts, top-8, expert width 512, plus 1 shared expert of width 512 (`expert_shared_feed_forward_length`). Hidden 2048, vocab 248,320, native context 262,144. The model is MTP-trained and, per the Part I census's filing of Janas's public docs, the GGUF keeps its MTP block.

Per-block tensor directory (names are the GGUF naming forms of this arch family, as filed for `qwen35` in this tree's own validator and for the routed/shared experts in the `qwen3next`/`olmoe` validators):

- **Common (9 per block):** `attn_norm.weight`, `post_attention_norm.weight` (the pre-FFN norm role, as in `qwen35` — no `ffn_norm`), `ffn_gate_inp.weight` (router), `ffn_gate_exps.weight`, `ffn_up_exps.weight`, `ffn_down_exps.weight` (routed experts, stored 3-D and folded by the tensor parser exactly as for `olmoe`), `ffn_gate_shexp.weight`, `ffn_up_shexp.weight`, `ffn_down_shexp.weight` (shared expert).
- **SSM block (+9 = 18):** `attn_qkv.weight`, `attn_gate.weight`, `ssm_alpha.weight`, `ssm_beta.weight`, `ssm_a`, `ssm_conv1d.weight`, `ssm_dt.bias`, `ssm_norm.weight`, `ssm_out.weight` (the `qwen35` SSM set) — with the `qwen35` branch's **exact** relational shapes: `attn_qkv` at [3·inner × hidden], `attn_gate` at [inner × hidden], `ssm_alpha`/`ssm_beta` at [dt-rank × hidden], `ssm_a` [dt-rank], `ssm_conv1d` at [inner·3 rows × conv-kernel] F32, `ssm_dt.bias` [dt-rank], `ssm_norm` [state], `ssm_out` at [hidden × inner].
- **Attention block (+6 = 15), fused-gate form only:** `attn_q.weight` at twice the Q width (the gate fused into the query projection, the `qwen35` form — this family carries no separate `attn_gate.weight` on attention blocks), `attn_k.weight`, `attn_v.weight`, `attn_output.weight`, `attn_q_norm.weight`, `attn_k_norm.weight` (per-head, head-dim wide, as in `qwen35`). A separate-gate attention block is refused (§0.2(2)); if the deferred real header census (§0.6) ever shows the separate form in a pinned file, widening this branch is that leg's named follow-on, recorded there — it is not pre-admitted here on speculation.
- **Globals (3):** `token_embd.weight`, `output_norm.weight`, `output.weight`.
- **MTP block (outside the per-block directory):** the census files the GGUF as keeping its MTP block; J-121's filed GGUF probe form for this family is the extra-block form `blk.<block_count>.nextn.*`. The validator neither requires nor forbids such tensors (extra tensors are not its business); their presence in any directory is graded only by J-076's classifier (§0.1 MTP). The exact head directory of a real Qwen3.6 GGUF is **not** asserted anywhere in this slice — no Aesir record files it, and only the deferred census (§0.6) can.
- **Vision tower (answered-locally):** the public record describes the checkpoint as natively multimodal with a vision tower. This slice's scope is the language-model GGUF under arch `qwen35moe` — the form the census's model matrix files and the form Aesir's per-arch verification grades. Vision tensors, if a combined file ever carried them, would be extra tensors outside this directory; no vision claim is made or implied.

**Census arithmetic (a prediction, stated as one):** 30 × 18 + 10 × 15 + 3 = **693** tensors for a head-free language file at the real geometry. Unlike J-123 — whose 843 was witnessed by J-022's filed header count — **no filed header count exists for this family to witness against**, because no file exists in Aesir's records. The 693 is therefore the directory's own arithmetic and a falsifiable prediction for the deferred census (§0.6), recorded as such and as nothing more; a head-carrying file would add its head tensors on top, in a count this slice does not predict.
