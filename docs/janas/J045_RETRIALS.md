## 1. Question and ground

**Question.** J-044 persists a measured placement + thread choice per pass kind, keyed by machine + model shape, with the provenance a second look needs (the key, the originating option, the decision, the measured-at stamp). But a learned choice is a measurement of a machine at a moment: the machine warms, drivers change, fans clog, a GPU arrives. When should Aesir re-measure a learned choice — occasionally, provably bounded, never on every open — and what happens when the new verdict differs: how is it adopted, and where is the change written down?

**Ground, and only that ground.** The learned file is J-044's (`core/learned_file.mojo`): `LearnedEntry` keyed by `MachineKey` + `ModelShape` with one `measured_at` stamp per entry, per-kind `LearnedPassChoice` with provenance (canonical J-036 `option_text`, chosen label/device/threads, J-040 decision name), `store_learned_entry` (same key replaced, other keys preserved, corrupt file refused untouched), `erase_learned_entry`, and the ABSENT discipline (a chooser REFUSAL stores nothing — a refusal is not a choice). The re-measurement instruments are the choosers themselves: J-040 (prompt), J-041 (reply), J-042 (drafts), each a live entry point over J-038's bounded harness + J-039's thread trials applying the one pre-registered decision rule; their records carry exactly the fields `learned_pass_from_choice` consumes. Manual supremacy is J-047's contract already on the face of J-044 (§4 there): a learned value is a default only, a MANUAL-FIXED choice is a hand choice whose provenance the file records — it is not a measurement. J-044 §9 roaded re-trials here deliberately and built none. No Janas source was opened; none was needed — every fact above is Aesir's own tree, and every design question the tree does not answer is answered locally in §8.

## 2. Where the code lives, and the shape of what is built

**A new dedicated module, not an extension of `learned_file.mojo` — decided on inspection, reason stated.** J-044's module is the persistence layer: it imports the option surface and the inventory facts and nothing else, and its fixed-offset format strictness is its whole contract. Re-trials are policy + orchestration — they import the persistence layer *and all three choosers* and drive them. Folding that into `learned_file.mojo` would invert the tree's dependency direction and entangle measurement policy with the format. Every Part III slice is one dedicated core module importing its predecessors, so this slice follows the pattern:

- **New module `aesir_engine/core/retrial.mojo`** (~880 lines): the cadence constants and the pure plan, per-kind eligibility, the adoption builder (pure), the retrial-log path rule + append, the apply orchestration (adopt → store/erase → log), and the live `run_retrial` (load → lookup → plan → choosers → apply).
- **Tests at `aesir_engine/tests/test_retrial.mojo`** (15 groups, §5/§10).
- **A comment block in `aesir_engine/aesir.mojo`** beside J-044's, recording the entry points and the consumption gap. The module is not registered in `tests/run_all.mojo` (the J-031/J-036–J-044 precedent: registration rides with a counted run the VM's memory gate does not permit; the standalone suite is the filed evidence).

**The cadence, pre-registered (stated in the module header and here before any J-045 live result).** A learned entry is due when *either* trigger fires:

- **AGE:** `now − measured_at ≥ 2,592,000 s` (30 days). Machines drift on this scale whether or not anyone opens a session.
- **OPENS:** the host has opened **≥ 25** sessions against the entry since its stamp **and** its age is **≥ 604,800 s** (7 days). Heavy use earns an earlier second look; the 7-day floor is absolute, so no burst of opens — however large — re-trials a fresh entry. The cadence is therefore bounded below by one re-trial per entry per week under any open pattern, and can never fire per-open, per-session, or per-token.

The clock and the counter are **injected**: `plan_retrial(entry, now, opens_since_measure, current_machine, current_model)` is a pure function (deterministic, unit-tested at exact boundaries), and the host owns counting its opens — J-044's versioned format holds no counter and is **not revised** by this slice (§8). A clock reading before `measured_at` (skew, a restored file) is never due: a negative age is not evidence about the machine, and the plan says so. **Key drift is not a re-trial:** an entry whose key no longer matches is not applied at all (J-044's lookup names the mismatched half and the caller measures fresh); `plan_retrial` states `KEY-DRIFT` for a host that asks, so the two roads are never confused.

**What is re-trialled.** A kind is re-triable when present *and* its decision is not `MANUAL-FIXED`. Due kinds are re-measured in the one re-trial, each under the entry's **own stored option** for that kind (the provenance J-044 kept — the re-trial re-asks the question originally asked), through the kind's own chooser, in the tri-device order the choosers already enforce (parked NPU excluded by J-037/J-038; this module adds no CPU-only assumption — it drives J-040/J-041/J-042 exactly as a session open would). An absent kind stays absent; a manual kind is carried verbatim (§4).

## 3. Adoption and the log, each unit-tested

The fresh records are converted through J-044's own builder (`learned_pass_from_choice`) and compared field by field (option, label, device, threads, decision) with the learned choice:

- **REPRODUCED** — every field equal: the kind keeps its choice.
- **CHANGED** — any field differs: the fresh choice replaces it.
- **REFUSED-NOW-ABSENT** — the fresh chooser refused (no choice): the kind becomes **ABSENT** in the adopted entry (J-044's discipline: a refusal leaves no learned default). If *every* kind of the entry ends absent, the entry is **erased** (`erase_learned_entry`) rather than stored as the nothing J-044 refuses at save — outcome `ERASED`.

Adoption (`apply_retrial`) stores through `store_learned_entry` (same key replaced, all other keys preserved, corrupt file refused untouched — J-044's discipline inherited whole), stamps the entry with the re-trial instant, and appends the change record to the **retrial log** at `retrial_log_path(path)` = the learned path + `.retrials.log`. The record states the key (machine + model renders), the trigger with the age and opens that fired it and the cadence bounds, the measured-at move, per kind the outcome with old → new choices rendered in J-044's own per-choice form, and the outcome (`KEPT` / `ADOPTED` / `ERASED`) with its reason. The store lands **before** the log append: the learned file is the authority and the log its audit trail; if the append fails, the error is raised after adoption and a host must surface it, never swallow it.

**Outcomes that are not re-trials write nothing.** `run_retrial` returns `SKIPPED` — no store, no log line — for a MISSING or REFUSED learned state, a lookup that does not apply, a not-due plan, a manual-only entry, or key drift; `append_retrial_log` itself refuses a SKIPPED outcome. The log records re-trials that ran, not checks that did not. A chooser or IO failure inside a due re-trial raises *before* any store lands (measurement precedes adoption), so a failed re-trial leaves the learned entry exactly as it stood.

## 4. Manual supremacy and reproduced-stamp honesty, on the record

**Manual supremacy (J-047's contract, not pre-violated here).** A `MANUAL-FIXED` kind is never re-measured, replaced, or argued with: it is carried into the adopted entry verbatim, its log line says so, and an entry whose present kinds are all manual is **never due** (`PLAN_MANUAL_ONLY`) at any age or opens count — proven at 400 days / 100,000 opens in the suite. This slice adds no ranking of hand choices anywhere; J-047 still owns the refusal surface.

**What happens to `measured_at` when a re-trial reproduces the choice.** The entry is re-stored with the stamp moved to the re-trial instant (outcome `KEPT`). That is the honest reading: the choice *was re-measured at that instant and stood*, so the stamp — J-044's "when the entry's choices were measured" — is then exactly true. Leaving the old stamp would re-fire the cadence at the next open (a re-trial on every open after the first due date — the unbounded behaviour the cadence exists to prevent); rewriting the choice as if new would fabricate a change. Carried manual kinds share the entry's single stamp; their provenance is their `MANUAL-FIXED` decision name, not the stamp, and the log's per-kind lines keep the two apart.

## 5. What the tests prove (PROVEN, VM, lightest target)

`test_retrial` — 15 groups. Groups 1–10 are pure (cadence, plan, adoption on injected inputs); 11–13 are the disk surface; 14 the skip discipline through the live entry point; 15 the live re-trial (§6):

1. **Cadence age:** 1 day keeps; one second under 30 days keeps; exactly 30 days is DUE (trigger AGE); 400 days due on age alone; an absent kind is never flagged due.
2. **Cadence opens, bounded:** 24 opens at 10 days keeps; 25 opens at 10 days is DUE (trigger OPENS); 100,000 opens at 1 day **keeps** (the 7-day floor is absolute); exactly at the floor fires; one second under keeps; a single open never fires; age+opens together name AGE+OPENS; a negative counter clamps to 0 and does not fire.
3. **Clock skew:** a clock before the stamp keeps at any opens, the reason naming the skew; age zero keeps.
4. **Manual supremacy (plan):** a MANUAL-FIXED kind is not re-triable, a measured kind is, an absent kind is not; an all-manual entry plans MANUAL-ONLY; a mixed entry is due for its measured kind only.
5. **Key drift:** machine / model / both drifted keys all plan KEY-DRIFT with the drifted half named.
6. **Adopt changed:** a mixed entry adopts the fresh reply verdict (threads + decision stand on the adopted entry), the manual prompt kind is carried verbatim (device + MANUAL-FIXED provenance), the stamp is the re-trial instant, and the log text carries trigger, old → new, CHANGED, CARRIED-MANUAL, ADOPTED.
7. **Adopt reproduced:** identical fresh choices keep the entry (KEPT), both kinds REPRODUCED, the stamp refreshed to the re-trial instant, choices unchanged.
8. **Adopt refusal:** a fresh refusal makes the kind ABSENT in the adopted entry while the surviving kind stands; outcome ADOPTED; log states REFUSED-NOW-ABSENT.
9. **Adopt all-refused:** a single-kind entry whose re-trial refuses ends ERASED with no entry to store; the log states the erasure.
10. **Adopt gate:** adoption under a non-DUE plan raises.
11. **Disk apply + log:** a seeded entry adopts on disk (reload LOADED, lookup APPLIED, new threads + stamp stand), the log file is created with trigger / old / new / outcome; a second, reproduced re-trial appends a KEPT record and refreshes the stamp on disk — the log grows by records, never rewrites.
12. **Disk apply erased:** an all-refused apply leaves a valid LOADED file with 0 entries and the erasure in the filed log.
13. **Log discipline:** appending a SKIPPED outcome raises and creates no log file.
14. **Run skips:** missing file, not-due entry, all-manual entry (at 400 days / 100,000 opens, reason naming MANUAL-ONLY), and corrupt file all return SKIPPED through `run_retrial` — the learned files byte-identical afterwards, no log written anywhere.
15. **Live re-trial:** §6.

## 7. Host contract (as built, nothing faked)

A surface opening a session: (1) loads the learned file and looks up its key exactly as J-044's contract states; (2) on APPLIED, calls `plan_retrial` with the current time (`learned_now_seconds()`), the number of sessions it has opened against this entry since the entry's stamp (its own count, kept in its own session bookkeeping — the format holds no counter, §8), and the current key; (3) **only** on DUE calls `run_retrial` (or drives the choosers itself and calls `apply_retrial` with the converted fresh choices) — never unconditionally at open: the plan is the gate, and the cadence's bound is the plan's, not the caller's memory; (4) prints `RetrialOutcome.log_text()` wherever it prints the learned report (J-050's explainability surface will cite both). **This slice wires the module into no live session path** — no session re-trials a learned choice yet, and none may claim to. The wiring point is the same `aesir.mojo` comment block where J-036–J-044 recorded their contracts. J-046 (within-tolerance proof) and J-050 (placement explainability) are the named consumers of the log and the refreshed stamps.

## 8. Answered-locally records (clean-room)

- **Q: What cadence — age, opens, or what else?** Janas's public documents name the behaviour (thread trials re-run as the machine warms; the learned configuration re-measured occasionally) but no cadence rule this road may copy, and Aesir's tree states none. Answered locally from Aesir's own evidence: J-039/J-040 showed per-sweep verdicts flipping under contention, so a cadence must be slow enough that re-measurement is an event, not a habit — hence the dual trigger (30-day age; 25 opens past an absolute 7-day floor) with the floor doing the bounding work. Machine-key *drift* was considered as a third trigger and rejected locally as a category error: a drifted key's entry is never applied (J-044 lookup), so there is nothing to re-trial — the fresh-measure road already owns it, and the plan names it KEY-DRIFT so the roads are never confused.
- **Q: Where does the opens counter live?** The learned file's format is J-044's, versioned and fixed-offset; adding a counter field is a format revision this slice does not make. Answered locally: the counter is *session bookkeeping, not learned state* — the host counts the sessions it opens against an applied entry and injects the count into `plan_retrial`, exactly as it injects the clock. The cadence's bound does not depend on the counter's persistence: the age trigger fires with no counter at all, and the floor bounds the opens trigger even if a host's count resets (a reset only ever *delays* an opens-triggered re-trial toward the age trigger — fail-safe toward keeping, stated here so no reader mistakes the counter for a security boundary).
- **Q: Where is the change logged — inside the learned file?** Answered locally: **beside it, not inside it.** The learned file is a strict fixed-offset state file whose parser refuses any line it does not know; an audit trail inside it would either break that strictness or be erased by the next store. The append-only log at `<learned path>.retrials.log` survives stores and erasures of entries, grows by records, and is written with the tree's proven pwrite + fsync discipline. (Whole-file erasure of the learned file does not erase the log — an audit trail that vanishes with the state it audits would be no trail; a host that wants both gone erases both paths, and `retrial_log_path()` names the second.)
- **Q: Why does a reproduced re-trial refresh the stamp instead of leaving the entry untouched?** Answered locally (§4): the stamp means "when these choices were last measured", and after a re-trial that is the re-trial instant. Leaving it would make the entry permanently due — a re-trial at every subsequent open, the exact unbounded behaviour the roadmap's "occasionally" forbids.
- **Q: Why are all three kinds re-trialled together when due, rather than per-kind ages?** The entry has one stamp (J-044's format), so per-kind ages do not exist to plan from; kinds differ only in *eligibility* (manual / absent), which the plan honours per kind. Splitting the stamp per kind is a format revision with no evidence behind it — recorded here as not built, not needed by anything measured.
- **Q: The decision-name table.** `run_retrial` converts chooser records through one local code→name table. Answered locally from the tree: J-041 and J-042 adopted J-040's rule *and its codes* unchanged (DEC_* 0..6 carry identical names in all three chooser modules — verified by inspection this slice), so one table serves all three; and the converted choice is re-validated by J-044's own decision check when the adopted entry validates, so a future code drift fails closed at adoption rather than persisting silently.
