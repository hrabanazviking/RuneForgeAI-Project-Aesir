## 1. Question and ground

**Question.** J-040/J-041/J-042 choose a placement per pass kind and J-043 plans prompt co-work — but every choice dies with its session: the choosers keep their record in a session holder that refuses a second decision and is gone at exit. How does Aesir persist the *chosen* placement + thread choice for each kind between sessions, keyed so a choice is only ever re-applied to the machine that measured it and the model shape it was measured for, in its own cache home and its own format — loaded at open, shown on request, erasable?

**Ground, and only that ground.** The option forms and canonical written forms are J-036's (`auto`, single, `a+b`, comma race; `PlacementChoice.describe()` is the canonical rendering the file stores options in). The machine facts are J-037's (`CpuFacts` / `GpuFacts`; unknown counts are −1, a hybrid split exists only when machine-stated). The choice records are J-040/J-041/J-042's — every one carries exactly `option_text`, `chosen_label`, `chosen_device`, `chosen_threads`, a decision name from the one pre-registered rule (MEASURED-WIN / DEFAULT-CONFIRMED / DEFAULT-BY-NOISE / SOLE-MEASURED / NO-MEASURED-FALLBACK / MANUAL-FIXED / REFUSAL), and `has_choice`. The model shape fields are the GGUF loader's (`GGUFModelConfig`: architecture, embedding/block/head geometry, feed-forward and context lengths, expert geometry). The persisted-record discipline is the tree's own (`core/state_vault.mojo`, `cli/model_preferences.mojo`: versioned header, fixed-order lines, FNV-1a checksum, atomic stage-fsync-rename writes, strict parse-or-refuse). **The binding consequence from Part II:** J-027 measured expert-map persistence and **rejected** it (no buildable row saves a net byte; the oracle ceiling nets exactly 0.000%) and recorded that J-044's learned file must not grow an expert-map section on that evidence — this slice honours it structurally (§2). J-045 owns re-trials: this slice stores their provenance (key, originating option, decision, measured-at stamp) and builds no re-trial logic. No Janas source was opened; none was needed — every fact above is Aesir's own tree, and every design question the tree does not answer is answered locally in §8.

## 2. Where the code lives, and the shape of what is stored

The Part III pattern — a small dedicated standalone module in `core/` plus a standalone lightest-target test suite, host contract in the module, a comment block in `aesir_engine/aesir.mojo`:

- **New module `aesir_engine/core/learned_file.mojo`** (~1,630 lines): the key halves and their builders, the per-kind choice record and its validation, the serialiser/parser, the cache-home path rule, the file IO (StateVault discipline at this file's bounds), the load/lookup/report surface, and store/erase.
- **Tests at `aesir_engine/tests/test_learned_file.mojo`** (13 groups, §5/§10).
- **A comment block in `aesir_engine/aesir.mojo`** beside J-043's, recording the entry points and the consumption gap. The module is not registered in `tests/run_all.mojo` (the J-031/J-036–J-043 precedent: registration rides with a counted run the VM's memory gate does not permit; the standalone suite is the filed evidence).

**What one entry holds.** A `LearnedEntry` = one `MachineKey` + one `ModelShape` + `measured_at` (unix seconds) + one `LearnedPassChoice` per kind (prompt / drafts / reply). A present choice holds: the resolved option in J-036 canonical form (provenance), the chooser's chosen label verbatim, the chosen device code, the chosen thread count (0 on a device-fixed choice — a device option does not fix a thread count, exactly as the choosers record), and the decision name. A kind whose chooser **refused** is stored **ABSENT**: a refusal is not a choice and leaves no learned default; an entry with no kind present is refused at save.

**The key halves, derived — never invented.**
- `MachineKey` derives from J-037's facts via `machine_key_from_facts(CpuFacts, GpuFacts)`: CPU model string (verbatim), logical / physical / package counts and the machine-stated hybrid split, plus GPU name, VRAM total, device count. No single machine-identity field exists in the tree; §8 records the derivation as answered-locally. A host holding no GPU probe facts keys the GPU as absent (a default `GpuFacts`) — stated as a host duty in the module header, because J-037's public observer exposes GPU truth only as rendered entry text (§8).
- `ModelShape` carries `GGUFModelConfig`'s shape fields one-for-one (architecture, embedding length, block count, head counts, feed-forward length, context length, expert count / experts used — both 0 for a dense file). The module does not import the loader (no Part III core module does); the host maps the config it already opened, via `model_shape(...)`.

**The format.** Versioned plain text, fixed line order, one block of 39 lines per entry: header `AESIR_LEARNED_PLACEMENT_V1`, `count=`, per entry the nine machine lines (CPU model and GPU name **hex-encoded** — the preferences file's treatment of free text that can carry arbitrary bytes; every other field is plain, eye-checkable text), nine model lines, `measured_at=`, then per kind six lines (`_present/_option/_placement/_device/_threads/_decision`; absent kinds write the canonical `-`/`0` empties), `end`; finally `checksum=` (FNV-1a over the whole body). Caps: 64 entries, 256 KiB. The parser walks the format by exact offsets and refuses **any** deviation — unknown, missing, reordered, or extra lines included. That strictness is also the J-027 enforcement: **there is no line an expert map could occupy**, and the round-trip test asserts no expert-map section exists in the serialised form.

**The cache home (answered-locally, §8).** The tree resolves no cache/config home today (the model store is a per-surface relative `.aesir/models`). In the tree's env style: `AESIR_LEARNED_FILE` (a full path) wins; else `$AESIR_CACHE_HOME/learned-placement.v1`; else `$HOME/.cache/aesir/learned-placement.v1`; else `.aesir-cache/learned-placement.v1` relative. `learned_file_path()` reads the live env; `resolve_learned_path(...)` is its pure form, unit-pinned (an env set empty counts as unset — an empty path names nothing).

## 3. Behaviours, each unit-tested

- **Save.** `save_learned_file(path, entries)` serialises whole (validation first — an invalid state never reaches disk) and writes atomically: parent directories created (the cache home's first save), stage in the same directory, fsync, rename, sync parent (the StateVault discipline). `store_learned_entry(path, entry)` is the learn-one operation: same key replaced, other keys preserved, count returned; into a MISSING file it starts fresh; into a REFUSED file it **raises** and leaves the corrupt bytes untouched (storing must never silently overwrite corruption — erasure is the explicit road).
- **Load at open.** `load_learned_file(path)` never raises. **MISSING** (no file) is the clean no-learned state — data, not an error. **LOADED** means parsed whole, checksum verified, every entry validated. **REFUSED** (corrupt, truncated, unknown version, oversized, empty, unreadable) carries the reason, **zero entries**, and leaves the file byte-identical — never a crash, never a partial apply.
- **Lookup.** `lookup_learned(load, machine, model)` is exact on both halves. Outcomes: `APPLIED` (with the entry); `MODEL-MISMATCH` (this machine has entries, none for this shape); `MACHINE-MISMATCH` (this shape has entries, none from this machine); `BOTH-MISMATCH`; `NO-ENTRY` (loaded, empty or — with entries — covered by the mismatch classes); `NOT-LOADED` (MISSING/REFUSED state, reason carried). A mismatch is data for the caller's fallback-to-measure path, never an error.
- **Validation refusals (save and parse share them).** The parked **NPU as a chosen device** — refused with the parked-ledger reason (a parked device may not re-enter as a persisted default; J-036 prompt *options* naming the NPU are a parse-surface fact for J-047's road, never a learned choice, because no chooser can choose an excluded device). Form/decision consistency: an explicit single/co-work option must file as MANUAL-FIXED, and MANUAL-FIXED requires one; an unknown decision name is refused; a non-CPU choice fixing a thread count is refused; options must round-trip through J-036's parser in canonical form (which also re-applies J-036's own legality — e.g. an NPU drafts/reply *option* is refused there, whole).
- **Show on request.** `LearnedLoad.report()`: state first (LOADED with count / MISSING clean / REFUSED with reason), then every entry rendered per key (machine line, model line, measured-at stamp, per-kind choice lines with device/threads/decision/originating option, absent kinds named absent), then the two standing sentences on the face of every report (§4).
- **Erase.** `erase_learned_file(path)` (never raises; reports erased / already-absent-clean / failed-with-reason) and `erase_learned_entry(path, machine, model)` (True when removed; False for a missing file or absent key; raises on a REFUSED file — per-key surgery on corrupt contents would guess; whole-file erasure is the honest road there). Erasing the last entry leaves a **valid empty file** (LOADED, 0 entries) — a state distinct from the erased-file MISSING, and the tests keep them distinct.

## 4. Manual supremacy and the J-027 binding, on the record

**Manual supremacy (J-047 next; not pre-violated here).** A learned value is a **default only**: it supplies the choice a session would otherwise have to measure, for exactly its key. An explicit `--prompt-on` / `--drafts-on` / `--reply-on` option (or env equivalent) overrides the learned value for its kind, always. Nothing in this module ranks, argues with, or rewrites a hand choice — the choosers already fix manual choices as MANUAL-FIXED without ranking, the format *records* that provenance rather than hiding it, and every report carries the sentence verbatim: *"learned values are defaults only; an explicit … option overrides the learned value for its kind, always."* The host contract (§6) binds applying surfaces to consult learned entries only for kinds the user left on auto.

**No expert maps (J-027).** The file holds placement + thread choices only. Every report carries the second standing sentence: *"expert maps: none — this file holds placement + thread choices only; no expert-map section exists (J-027 measured rejection)."* The parser's fixed-offset strictness makes the absence structural, not editorial.

## 5. What the tests prove (PROVEN, VM, lightest target)

`test_learned_file` — 13 groups. Groups 1–6 are pure (keys, codec, validation, paths); 7–13 are the disk surface and the live run (§6):

1. **Keys:** identical fixture facts derive equal keys; a perturbed count breaks equality; renders name the CPU/GPU/arch/experts; architecture outside `[a-z0-9._-]` refused; a dense shape claiming used experts refused.
2. **Round trip:** two entries serialise (header, `count=2`, no expert-map section) and parse back field-exact (keys, stamp, per-kind device/threads/decision/labels, manual GPU choice with threads 0); re-serialisation is **byte-identical**.
3. **Refusal kind absent:** a REFUSAL record builds ABSENT with canonical empties; absence survives the round trip; an all-absent entry is refused at save.
4. **NPU refused:** an entry whose prompt choice names the NPU is refused at save, the reason naming the parked ledger.
5. **Validation refusals:** auto+MANUAL-FIXED, explicit option + measured decision, unknown decision name, non-CPU choice fixing threads — all refused.
6. **Path resolution:** file env > cache env > HOME > relative fallback; an empty file env falls through.
7. **Disk save/load:** missing loads MISSING (clean report, no entries); save writes the headered file; load returns LOADED with both entries; the exact key APPLIES with its thread choice.
8. **Lookup mismatches:** model / machine / both / no-entry (loaded-empty) / not-loaded (missing) — each named, each with its reason.
9. **Store:** append (1→2), same-key replace (count stays 2; new threads + new stamp stand), corrupt-store raises and leaves the corrupt file byte-identical.
10. **Corrupt loads:** garbage, truncated-half, bit-flipped body (checksum), unknown-version header, empty file — **all REFUSED whole**: zero entries, reason stated, file left byte-identical, lookup from the refusal applies nothing.
11. **Erase:** per-key removal; absent key False; last-key erasure leaves a valid empty LOADED file; whole-file erase reports; post-erase load is MISSING; erasing an absent file is the clean already-erased state; per-key erase on a missing file is False.
12. **Report:** state line, both keys' models, per-kind lines (incl. `drafts: absent`), measured-at provenance, and both standing sentences (§4).
13. **Live round trip:** §6.

## 7. Host contract (as built, nothing faked)

A surface opening a session: (1) observes the inventory + CPU facts (J-037), builds the `MachineKey` from the facts it holds, and maps the opened model's `GGUFModelConfig` onto a `ModelShape`; (2) calls `load_learned_file(learned_file_path())` once — MISSING and REFUSED are data, printed beside the device line with their reasons, never raised through open; (3) for each kind the user left on **auto**, calls `lookup_learned` and, on APPLIED, seeds that kind's session choice from the entry instead of measuring (an explicit option always wins — §4); (4) when it measures a fresh choice, stores it via `store_learned_entry`, stamped by `learned_now_seconds()` (J-045's provenance); (5) prints `LearnedLoad.report()` on request (the surface J-050's explainability report will cite). Erasure is the two erase entry points. **This slice wires the module into no live session path** — no session consumes a learned choice yet, and none may claim to. The wiring point is the same `aesir.mojo` comment block where J-036–J-043 recorded their contracts. J-045 (re-trials) consumes the `measured_at` + key + option provenance; J-047 (manual supremacy) consumes the defaults-only contract; J-104 (chat saved config) reconciles this file with the chat surface's saved configuration as one story.

## 8. Answered-locally records (clean-room)

- **Q: What is Aesir's cache home?** The tree resolves none — the model store is a relative `.aesir/models` path chosen per surface (`config.mojo`, the CLI surfaces), and no XDG/HOME-derived home exists anywhere in the tree (verified by search this slice). Answered locally in the tree's own env style (§2): `AESIR_LEARNED_FILE` > `AESIR_CACHE_HOME` > `$HOME/.cache/aesir` > `.aesir-cache/`, file name `learned-placement.v1`. The XDG-shaped middle step follows the platform convention a cache home is expected to have; the env overrides are Aesir's own names, consistent with `AESIR_PROMPT_ON` / `AESIR_EXPERT_CACHE_BYTES` precedent.
- **Q: What identifies a machine, for keying?** No machine-identity field exists in the tree. Answered locally from J-037's facts: the key is *derived* from the inventory's own measured truth (CPU model + topology counts + machine-stated hybrid split + GPU name/VRAM/count), so two machines key alike only when the inventory itself cannot tell them apart. A hostname or a hardware UUID was considered and rejected locally: neither is an inventory fact in this tree, and keying on unmeasured identifiers would contradict J-037's discipline (state what the machine's sources state).
- **Q: What identifies a model, for keying — its file? its name?** Answered locally from the loader: the **shape** (`GGUFModelConfig`'s geometry fields), per the roadmap's own words ("keyed by machine + model shape"). A file path or catalogue name was rejected locally: the same shape reached by two paths is the same placement question, and a renamed file must not orphan learned choices; conversely two different shapes at one path *must not* share choices, and only the shape key guarantees that.
- **Q: J-037's observer returns rendered GPU text, not `GpuFacts` — where do GPU key facts come from?** Answered locally from the tree: the key builder takes the facts a host holds (`machine_key_from_facts(CpuFacts, GpuFacts)`); J-037's `_probe_gpu` is module-internal today, so a surface that wants GPU-true keys needs the probe's facts exposed — recorded as a named gap for J-050/the Part III gate (§9), not papered over here. On GPU-less machines (this VM) the absent keying is exact.
- **Q: Why is a refusal stored as ABSENT instead of being persisted as a refusal record?** Answered locally from the file's purpose: the learned file supplies *defaults*. A refusal is the absence of a choice; persisting it as a value would let yesterday's refusal silently decide today's session without measuring — the opposite of the choosers' own discipline (their REFUSAL records carry "no placement is claimed"). The measured-at provenance of real choices is what J-045 re-trials; a refusal has nothing to re-trial.
- **Q: Why does storing into a corrupt file raise instead of starting fresh?** Answered locally: corruption is evidence (of a torn write elsewhere, a disk fault, a hand edit). Silently replacing it would destroy that evidence and could mask a recurring fault; the honest roads are the ones the module provides — inspect via the REFUSED report, erase explicitly, then store. Same reasoning for per-key erasure refusing on a corrupt file.
- **Q: Does the co-work slice (J-043) contribute a learned value the prompt kind must carry separately?** Answered locally from J-043's own record: its survived device options are *placement choices for the prompt kind* (a MANUAL-FIXED or race/auto outcome whose label is the pair), already representable in the prompt kind's choice; its thread-partition analogue creates **no** device option and therefore nothing learnable. No separate co-work section exists, and inventing one would persist a category J-043 explicitly did not produce.
- **Q: Should the drafts kind be learnable at all before Part V builds the pass?** Answered locally: yes, as a *record* — J-042's chooser produces real records today (fallbacks and MANUAL-FIXED choices with their unmeasurable state), and J-083's draft configuration surface is named as persisting via this file. What is *not* learnable is a drafts **use**: J-036's `require_draft_check_use()` gate stands untouched by anything here — storing or applying a drafts default never calls it, and using one still fails closed until Part V.
