## 1. Verdict — and the rule, pre-registered in the module header

**J-083 closes CLOSED-WITH-DEFERRED-LEG:** Aesir now has the draft configuration surface the roadmap names. One shared scan/resolve serves both the chat and the server surfaces, so parity is by construction and is graded field-by-field; every contradiction is refused by name rather than resolved by precedence; a configured pair or head is validated by the road's already-recorded gates (J-074, J-077), never by a second gate built here; and a validated configuration persists through Part III's learned file, in that file's own format, with V1 files byte-identical to J-044's. Configuring is not using: the fail-closed use gate stands for every configuration while the road's two global blockers stand, and the live leg is **DEFERRED-WITH-REASON** (§6), re-cited at the J-086 gate.

**The verdict / refusal rules (pre-registered in the header of `core/draft_config.mojo`, written before the code; the module's tests grade exactly these):**

- **One proposer source per configuration.** `--mtp` selects the target's own MTP head (J-071 SLOT_HEAD, PROPOSER_MTP_HEAD); `--draft <model>` selects a separate draft model (PROPOSER_CROSS_MODEL's slot). Stating both is refused by name (**REFUSE_CONTRADICTORY_SOURCES**): a session runs one proposer slot per round (J-072), and a configuration that names two sources has no honest reading.
- **`--mtp` with `--no-mtp`, in any layer or across layers, is refused by name (REFUSE_CONTRADICTORY_MTP).** Precedence never silently resolves a hand contradiction. `--no-mtp` with `--draft` is **NOT** a contradiction: `--no-mtp` disables the head source only, and the configuration records mtp=off beside the draft-model source.
- **k defaults to J-072's LOOP_K_INITIAL** and is validated against the selected source's cap, read from J-071's `plan_proposer` on every validation (model sources 15; no-source configurations validate against the band cap 15 the same way). Outside 1..cap is refused by name (REFUSE_K_OUT_OF_BAND), naming the cap and its owner. The conversation proposer's tighter cap (8) binds no configuration here: conversation drafts are not a configurable source on this surface (J-071's slot exists; no flag states it), and that exclusion is stated, not implied.
- **A configured `--draft` pair is validated by the recorded pair gate, not by this module's opinion:** `validate_draft_model_pair` calls J-074's `evaluate_pair` with the configuration's k and the caller-stated pair facts, and any inadmissible verdict is raised by the gate's own reason name (REFUSE_MISSING_FILE, REFUSE_UNKNOWN_FAMILY_PAIRING, REFUSE_TOKENIZER_UNVERIFIED / _MISMATCH, REFUSE_K_OVER_CAP, REFUSE_BUDGET_EXCEEDED). A configured `--mtp` is validated by J-077's `evaluate_mtp_admission` over the caller-stated tensor directory, raised by J-077's refusal line (REFUSE_NO_MTP, REFUSE_NOT_PROVEN). This module builds no second gate.
- **Persistence is Part III's learned file, in its own format:** a validated configuration is stored into a LearnedEntry's draft section (`core/learned_file.mojo`'s J-083 extension: same file, same cache home, same atomic writes and checksum; V1 files without draft configurations are byte-identical to J-044's) through `store_learned_entry`, and read back through `load_learned_file` + `lookup_learned`. There is no second config store. Storing follows `store_learned_entry`'s own semantics: one entry per machine+model key, replaced whole — a host holding learned pass choices for the key merges them into the entry (`apply_draft_config`) before storing, exactly as the learned file's contract states.
- **THE USE GATE STANDS.** Configuring is not using. No proposer implementation exists in-tree (G-PROPOSER) and no verify-pass executor exists in-tree (G-EXECUTOR); J-036's `require_draft_check_use()` still raises and the facade's `speculative_generate` still raises not-implemented. `require_draft_config_use()` therefore raises for **every** configuration — a configured source by the blockers' names, an unconfigured one by REFUSE_NO_SOURCE — and nothing in this module calls a session, lifts a gate, or honours a stored configuration silently. A stored configuration records and validates intent; that is all it does today.

## 3. The surface's behaviour, as graded

The suite grades the §1 rules directly, and its filed run (`j083_test_output.txt`) is the evidence; the load-bearing behaviours:

- **Parity is identity, not resemblance:** six argv shapes (empty, `--mtp`, `--no-mtp`, `--draft`, `--draft` + `--draft-k`, `--no-mtp` + `--draft`) are resolved through both entry wrappers and compared field-by-field and by the canonical `describe()` string — identical on every field in every case, because both wrappers call the one resolver over the one scan.
- **Contradictions refuse in every layer arrangement:** `--mtp` + `--no-mtp` in one argv, `--mtp` on cli with `--no-mtp` on env, and `--mtp` + `--draft` — 3/3 refused by name. Precedence is exercised separately and honestly: cli k beats env k while an env-only draft model stands, each field keeping its own layer tag.
- **The caps are J-071's, read live:** `draft_k_cap` returns 15 for both model sources through `plan_proposer`; k = 15 is admitted, k = 0 and k = 16 are refused for both sources, and malformed k text (`x`, `-1`) is refused by the strict unsigned-decimal grammar — 5/5.
- **The recorded gates decide:** through J-077, a stated tensor directory carrying the MTP head tensors is admitted (proposer kind MTP_HEAD, cap 15) and a headless directory, an unread directory, and a wrong-source configuration are refused — 3/3. Through J-074, the documented pair shape (same family, verified identical tokenizers, drafter smaller than target) is admitted at the configuration's k, and missing-file, unverified-tokenizer, and not-smaller pairs are refused.
- **Persistence round-trips exactly:** a `--no-mtp` + `--draft` + k=6 configuration persists to a V2 file, loads back field-identical, replaces whole under the same key (count stays 1, the replacement's values win), misses cleanly by name on a perturbed model shape (MODEL-MISMATCH) and on a missing file (MISSING), and a corrupt file applies nothing (REFUSED). A pass-choice-only entry serialises as V1 and parses back with no draft configuration; a merged entry (pass choices + draft configuration, via `apply_draft_config`) round-trips with both halves intact.

## 4. What this settles, and what it does not

- The road's configuration question is settled in Aesir's own words: there is now exactly one way to state a draft configuration, it means the same thing on both surfaces, its contradictions and out-of-band values refuse by name before any gate or store is touched, and its persistence rides the file Part III already owns — no second config store, no second vocabulary (the learned file's draft-source and mtp codes are the surface's codes, defined once in `core/learned_file.mojo` and shared).
