## 1. Verdict — and the pair rules, stated before building

**J-078 closes CLOSED-WITH-DEFERRED-LEG:** the host-side assistant-pair machinery is built and proven — a pure pair gate that decides admissibility for a stated (target, assistant) pair under pre-registered rules, admits a labelled SIMULATED Gemma-pattern pair in both of its forms, computes the pair's exact memory budget through the road's existing shared accounting, and refuses every inadmissible pair by name with its reason. The measured-gain leg is **DEFERRED-WITH-REASON** (§6): no Gemma pair file is reachable tonight, and no proposer/executor/session wiring exists to run one — so no gain is claimed, and none is faked.

- **The rules (pre-registered; the module header is their normative text).** A pair is admissible only when all nine hold; the first failure is the verdict's named reason:
  1. **Named, present files** — both requests name a file (`REFUSE_EMPTY_FILE_NAME`) and both files exist (`REFUSE_MISSING_FILE`).
  2. **Both files censused** — both tensor directories actually read; an unread directory refuses as `REFUSE_UNCENSUSED_FILE` (names carried beside it are never trusted, counted, or classified — J-076/J-077's rule), and an empty directory on either side refuses as `REFUSE_VOCAB_ONLY`.
  3. **Same family (the Gemma pattern)** — target and assistant are the same known architecture family (J-074's codes); cross-family or any unknown family refuses (`REFUSE_FAMILY_MISMATCH`).
  4. **Assistant form** — exactly one of two forms: **head form** (the assistant's directory carries head tensors and J-077's gate admits it as the *assistant* proposer — a WITH_MTP file whose heads are nextn/mtp is an MTP head file, J-077's own kind, and refuses here as `REFUSE_ASSISTANT_FORM` rather than being re-filed as an assistant) or **standalone form** (an ordinary model directory with zero heads — a separate small model admitted under J-074's pairing discipline). Both forms run under J-071's one assistant shape.
  5. **Tokenizer identity, verified not assumed** — J-074's rule unchanged: no comparison run → `REFUSE_TOKENIZER_UNVERIFIED`; a divergent run → `REFUSE_TOKENIZER_MISMATCH` with the first divergence index carried in the verdict.
  6. **Materially smaller** — J-074's bound unchanged: assistant resident bytes at most half the target's (`REFUSE_ASSISTANT_NOT_SMALLER`).
  7. **Budget share (this slice's rule, answered-locally §7)** — the assistant's total stated footprint (resident + KV allowance + scratch) is at most **one quarter** of the pair's total stated footprint (`REFUSE_OVER_BUDGET_SHARE`). Rule 6 grades resident bytes alone; this rule grades everything the assistant asks the pair to carry.
  8. **k inside the assistant cap** — 1..15, read from J-071's `plan_proposer(PROPOSER_ASSISTANT_MODEL).max_k` every time, never restated (`REFUSE_K_OVER_CAP`).
  9. **One budget for both files** — both sides' resident bytes, KV allowances, and scratch summed and sized **once** through J-026's `plan_shared_cache_pool` (OS headroom charged once for the process); a summed reserve leaving no pool budget, or one below the one-token floor, refuses (`REFUSE_BUDGET_EXCEEDED`).

## 4. The pair's memory budget — exact arithmetic on stated inputs (SIMULATED fixtures)

The roadmap asks for "loading both, the pair's memory budget". The budget is an accounting over stated quantities, proven as arithmetic; the quantities below are the suite's **SIMULATED** fixture sizes (an 8 GiB-class Gemma target against a 1 GiB-class assistant), not measurements of any real file — no Gemma file exists here to measure (§3).

**Head form** (assistant reads the target's KV, its own KV allowance stated as 0): target footprint 8,000,000,000 + 1,000,000,000 + 100,000,000 = **9,100,000,000 B**; assistant footprint 1,000,000,000 + 0 + 50,000,000 = **1,050,000,000 B**; pair footprint **10,150,000,000 B**; assistant share **103 per mille** (inside the pre-registered 250 bound). Pair sizing through the shared pool (free 20,000,000,000 B, total 32,000,000,000 B, no hard cap, per-token routed 1,000,000 B): summed resident 9,000,000,000 + summed KV 1,000,000,000 + summed scratch 150,000,000 + OS headroom 6,400,000,000 (total // 5, charged **once**) = reserve **16,550,000,000 B**; pool budget **3,450,000,000 B**, above the one-token floor.

**Standalone form** (assistant states its own 200,000,000 B KV allowance): assistant footprint **1,250,000,000 B**; pair footprint **10,350,000,000 B**; share **120 per mille**; reserve **16,750,000,000 B**; pool budget **3,250,000,000 B**.

The Mojo suite proves the verdict's sizing is **identical, field for field, to a direct `plan_shared_cache_pool` call over the summed quantities** — the pair is never sized per-model and the headroom is never charged twice (the J-026 over-commit this function exists to replace).
