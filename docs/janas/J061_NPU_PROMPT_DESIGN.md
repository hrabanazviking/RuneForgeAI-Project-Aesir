## 2. Inspection — what an NPU prompt pass would bind into, as the tree stands (PROVEN from the tree)

**The placement surface already speaks NPU.** `core/placement_options.mojo` (J-036) defines `DEVICE_NPU` beside cpu/gpu, parses `--prompt-on npu` (and its env equivalent) as a legal prompt placement, and **already refuses the NPU for draft-check and reply passes at parse time, whole, never trimmed** ("the NPU never takes a draft-check pass and never takes a reply pass"). The kill switch `--no-npu` / `AESIR_NPU=0` exists. What does not exist is any *consumption*: J-040's chooser records present NPU candidates as UNMEASURABLE-WITH-REASON (no device executor), and no session consumes a prompt placement at all tonight. The design therefore binds at a surface that exists and is honest about its gap.

**The inventory's NPU entry is a ledger state, not a device.** `core/device_inventory.mojo` (J-037) reports the NPU strictly from Aesir's own ledgers and never probes: its states are PARKED / NOT_PRESENT / NOT_PROBED, and on this road the entry is **PARKED** — because the one NPU in Aesir's ledgers is the **Hailo-10H**, owned by the parked finish-line campaign. This is the slice's central silicon fact, stated plainly: **the census's NPU is an Intel Core Ultra NPU** (OpenVINO IR graphs Janas writes itself, opened through Intel's Level Zero driver 1.38.0, user in the `render` group, no Windows path — census J-004), while **Aesir's ledger NPU is a different chip from a different vendor with a different compiler road**. This design is therefore silicon-agnostic at the placement/account layer and binds to *neither* stack: it does not design OpenVINO graphs, and it does not design Hailo programs. Which silicon, if any, an Aesir NPU prompt pass ever executes on is the executor question (§4, N1/N2) behind J-062's gate — not a premise this slice may smuggle in.

**The prefill forms the pass would join.** J-053's anatomy stands: host batched (cap 256, pure-prefill chunks, head paid once), host per-token, Llama 3 CUDA width-1/tile-4, Gemma 4 CUDA width-1, OLMoE width-1 `step` (whose per-token head, F1, is J-058's G1 debt). An NPU form is a *new row* in that anatomy — it reuses none of their executors, and its by-construction columns (passes, head passes, KV bytes) must be stated in J-053's vocabulary when it is built, or its walls are not comparable (§9's recipe does so).

**The progress account exists and is prompt-shaped.** `core/prompt_progress.mojo` (J-059) provides the record, the boundary/step/final discipline, and both render forms for *prompt reads*, with its watched bound set in tokens (≥ 1,024). Preparation is not a prompt read, and the census's documented preparation reporting happens at tens of units ("preparing the NPU 12/25, 8 s") — a literal reuse of J-059's plan would silence every real preparation. §6 states the adaptation and §10 records it as answered-locally; the record *shape* and rules R2–R5 are J-059's, the R1 bound is preparation's own. No live surface consumes either account yet (J-059's W1–W4 stand), and preparation inherits that gap as its N4.

**The 8-bit machinery that exists is not a copy builder.** The tree reads GGUF Q8_0 blocks (block scales, not per-row scales) and carries a SmoothQuant W8A8 path in `core/external_quantization.mojo` (per-*matrix* weight scale + activation quantization for its own GEMM shape). Neither produces what the census describes — a per-row-scaled 8-bit copy of an arbitrary directory matrix, computed for a device that computes in f16. That builder is a missing piece (N3), named, not approximated by pointing at the neighbours.

**The contention planner exists and is reused, not restated.** `core/placement_pressure.mojo` (J-048) already decides duplicate copies against the expert cache (rule 3: cache-class unless a hand names them; admitted only where the cache keeps its floor). This slice's contention verdict calls that planner directly (§5), so the invariant has exactly one implementation on the road.

**What the census documents (J-004, the design's only Janas ground).** Prompt blocks ≥ 64 tokens; never reply, never draft-check. Dense-whole for dense models whose layers fit (~3.7 GB on the census laptop; Qwen3, Qwen3.5, Gemma 4 dense named; published reading gains restated in the census, Janas's numbers). Split-block: NPU computes a layer on one half of a block while the CPU computes attention (or Qwen3.5 recurrence) on the other; leftover layers stay CPU. Resident-products for larger/MoE: attention, recurrent layers, shared experts; routed experts stay CPU/GPU — and on mixtures the census's own laptop kept the GPU's fast prompt over this form (30B-A3B: 133 vs 90–110 tok/s), an ordering this design records without inheriting (Aesir's chooser measures its own machine, J-040's law). Copies: 8-bit, per-row scale, computed in f16, norms in f32; optional 8-bit activations on dense Qwen3 only. Preparation: one-time per session, 7.5–53 s by model (Janas's figures), progress on the chat status line, compiled graphs cached (a named model's second preparation at 3.8 s vs 36 s first). Contention closure as §7 prices. Agreement: most-likely-token agreement vs llama.cpp within ±7 of 512 on eight models, with the Gemma-4-26B product-placement row agreeing less (363 vs 398) and therefore reading only when asked — the one census row this design promotes into a rule (§8).

## 3. The design — how an NPU prompt pass binds into Aesir

**Lifecycle, in order.** (1) *Resolve:* at model open the surface resolves placement exactly as J-036/J-047 prescribe (options, precedence, supremacy; a killed or absent NPU refuses with the inventory's reason). (2) *Inventory:* J-037's entry must state an NPU present-and-usable; tonight it states PARKED, and the design's honest consequence is that step (3) cannot be reached on any machine tonight — the account in §5 is still the contract a post-gate open follows. (3) *Account:* the host derives the form's copy set from the opened file's directory (per-form sets below), calls `plan_npu_prompt_prep`, and charges the plan's footprint through `evaluate_npu_contention` per contested pool. CLOSED → no preparation, the prompt pass runs where it would have run; REFUSED → the open stops with the planner's numbers stated. (4) *Prepare:* one-time per session — build the copies, compile one graph per NPU layer, cache copies + graphs keyed by the model file's sha256 and the copy-set shape in Aesir's own cache area (model files are never modified — the census's manners and Aesir's alike); progress reported through §6's account. A cache hit prepares nothing new (0 bytes to write) but the footprint is charged in full at step (3) either way, because cached copies occupy the pool exactly as fresh ones do. (5) *Read:* prompt blocks of ≥ 64 tokens execute on the NPU form; shorter prompts, and every non-prompt pass, never touch it. The bench/measurement harness prepares before measuring (the census's `janas-bench` discipline; Aesir's J-038 analogue: an NPU candidate is UNMEASURABLE until preparation exists to measure through).

**The three forms and their copy sets** (a matrix is in the copy set iff the form computes its products on the NPU; scales are per output row):

| Form | Takes (copied as 8-bit + per-row scale) | Stays host/native | Layer rule |
|---|---|---|---|
| **Dense-whole** | Every block matrix of every layer: Q, K, V, O, gate, up, down | Embedding (a lookup, never a product), LM head + sampler (host, paid once — the pure-prefill discipline), norms (carried at f32 beside the copies, never 8-bit) | **All** layers; a partial dense model is not this form and the planner refuses to call it so |
| **Split-block** | The same block matrices, for the NPU's layers only | Attention (and Qwen3.5-class recurrence) on the CPU for *every* layer — the block's halves are computed concurrently, NPU layer-products on one half, CPU attention on the other; leftover layers entirely host | NPU layers a strict subset is the normal case; leftover count is stated on the plan, never hidden |
| **Resident-products** | The resident set only, per layer: attention Q/K/V/O, the router, and a shared expert where the arch carries one | **Routed experts — never copied, never NPU-computed under this form** (they stream; copying them is the contention failure mode the census's closure row prices); embedding, head, norms as above | Products exist per layer, so the copy set spans every layer's resident weights |

**The pass law (what the NPU may never take), enforced at three layers so no single gap reopens it:** J-036's parser refuses `--drafts-on npu` / `--reply-on npu` whole (exists tonight); this slice's planner returns **no plan shape** for PASS_DRAFTS or PASS_REPLY — the refusal is by construction, not a flag a caller can clear; and no executor exists to honour a smuggled request (N1). The same construction refuses NPU preparation for prompts under 64 tokens: the pass itself is not refused — it simply runs on CPU/GPU, unprepared-for-NPU, which is the census's own shape (the NPU is "left out", the session proceeds).

**Execution shape (the form's by-construction columns, for the day it is built).** Blocks at the host's chunk discipline (cap 256 default, the J-053 host row's width — answered-locally, §10); pure-prefill: the NPU form returns hidden states, the host pays the LM head exactly once per prompt; KV is written in the host's exact layout by whichever side computes attention (dense-whole: the NPU side, and its KV bytes are J-053-accounted per token identically; split-block: the CPU side, by construction); synchronisation once per block, never per token. The 8-bit activation mode is a per-plan flag, dense forms only, default off, and a *separately graded* variant (§8) — it changes no copy byte (§5's test pins this).

**Accelerator-first framing, honestly bounded.** The road's order is NPU → GPU → CPU, and this design gives the NPU the prompt pass — the widest, most parallel pass — exactly as that order intends. It does **not** assert the NPU wins anything: the census itself records a machine where the GPU's prompt beat the NPU's product form on mixtures, and Aesir's chooser (J-040) may only rank an NPU candidate from measurements through a built executor. Until then the NPU's placement state is what J-040 already records: named, legal, and UNMEASURABLE-WITH-REASON.

## 6. The pre-registered rules (stated in the module header before the filed shapes were priced)

**The copy rule.** Payload = elements × 1 B; scales = rows × 2 B (one f16 scale per output row — the census states the per-row scale and f16 compute, not the stored width; f16 storage is the answered-locally choice, §10); norms are never in the copy: norm carriage = norm elements × 4 B (f32). Footprint = copy total + norm carriage, and the footprint — not the copy alone — is the contention charge, because both occupy the contested pool.

**The preparation progress discipline.** Units = NPU layers (one graph each). Records exist only at unit boundaries (a unit completes, then a record may speak); a record emits iff it crosses the next 10% step the previous unit had not reached, plus the final unit always; at most 10 records at any unit count ≥ 4; below 4 units the preparation is silent. This is J-059's R2–R5 verbatim in shape and its R1 adapted in bound (tokens → units), for the reason §2 states: the census's own documented reporting happens at 25 units, and a discipline that silenced it would contradict the behaviour being designed. The render is the census's line — `preparing the NPU <done>/<total>` with `, <s> s` appended only when the caller supplies elapsed seconds; the account never invents a time (J-059's O2 honesty, carried).

**The contention rule is J-048's, unmodified.** No new threshold is stated here: the floor is J-028's floor, the copy class is J-048's rule 3, the manual shapes are J-047/J-048's. §7 applies it; it does not amend it. (J-065 owns the *conditional live* application of that rule to an NPU's copies if the gate opens; this slice's application is the abstract planner call the roadmap's J-061 text requires — the design's contention price — and §7 keeps the two apart.)

## 8. The faithfulness debt to J-060's battery (named explicitly)

**Every NPU prefill form is, tonight, a NOT_GRADED cell in J-060's matrix** — the battery (§4 of its doc) gains three design-side rows (dense-whole, split-block, resident-products) × the arch rows they apply to, all entering as NOT_GRADED with N1/N2/N7 as their gating items, exactly as the unbuilt block/chunk forms entered. Nothing in this slice's accounting may be cited as a faithfulness grade: §7 prices bytes, and bytes are not ranks.

**How the debt is discharged, when the gate opens** (J-060 §7's order, unmodified): ids first — the NPU form's generated ids vs the same arch's host reference form on the same file/raw prompt, token for token, any divergence bisected as a defect (the B1 precedent); then teacher-forcing rank + logit gap via the ggml **CPU** comparator on the raw prompt — never `llama-cli --single-turn`, CPU-vs-CPU only, the four-condition comparator check filed per cell, step-0 boundary as its own class, agreement counts beside the account never instead of it. The pass bar is J-060's rule: FAITHFUL or NEAR_TIE (rank ≤ 2 **and** sub-logit gap, both conjuncts).

**Why the debt is real and not a formality.** The copies are 8-bit with f16 compute where the host reference computes from K-quant/f32 shapes — a different rounding road by construction (the census's GPU fast-prompt row records the same genus of cost on its own engine: positions changing most-likely token under group rounding). Three design rules follow, stated here so a later builder cannot discover them by accident: (i) **resident-products starts ask-only** — until its cell grades, the form runs only where a hand names the NPU for the prompt pass, carrying the census's Gemma-4-26B caution (product placement agreed less; "there the NPU reads only when asked") as an Aesir design rule, not a Janas anecdote; (ii) **8-bit activations are a separate cell**, never folded into the weights-only grade — the census itself calls the mode "faster, less exact", and a combined grade would hide which approximation cost what; (iii) **split-block grades per form, not per half** — the join is part of the form, and a half-grade that passed while the joined form diverged would be a comparator-artifact-shaped trap. Janas's published agreement figures (±7 of 512 on eight models) are recorded in the census and **deliberately not restated here as expectations**: they are another engine's evidence on another machine, and J-060's discipline exists precisely to keep such numbers from standing in for Aesir's own.
