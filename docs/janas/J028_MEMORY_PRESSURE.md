## 1. The question, and the design it answers to

Free memory at open is not free memory forever. A cache sized to the open moment becomes an overcommit when another process takes RAM mid-run; defended, it pushes the machine into swap — the failure Janas's own README warns of for its cache on a low-headroom desktop. J-017 §5.3 decided Aesir's ordering in advance, and this slice builds exactly it:

- **The cache sheds before anything else does.** Under pressure the expert cache shrinks first; the resident set and the KV cache are never cannibalised to feed it, and it is never defended at the cost of swapping the machine.
- **Shrink sheds policy-ordered entries** (for the shipping fsketch policy: lowest sketch frequency, ties by LRU — the cache's own `shed_to_resident` order), **pins in-flight experts**, and **completes within the current token**.
- **At the floor the run refuses cleanly with the reason stated.** The floor is J-018's: one token's full routed demand (below it a cache cannot hold a single token's working set). At exactly the floor the run continues — barely, by definition; below it, refusal.
- **Regrow is capped.** When pressure eases the budget may rise again, but never above the open-time budget and never above the hard cap: recovered memory is not a licence to outgrow what open-time sizing granted.

**Answered-locally record:** Janas's public documentation names the hazard and its cache cap, but specifies no mid-run shrink policy, cadence, or refusal rule (Part I census, J-002). The policy, cadence, and refusal shape below are Aesir's own, derived from J-017 §5.3/§4 and the J-018 mechanisms. No Janas source was opened.

## 2. What was built, and the verdict rule — stated before measuring

All in `aesir_engine/core/expert_cache.mojo`; `moe_session.mojo` gains only the documented host contract (as in J-026):

- **`plan_pressure_budget(free_now, total, hard_cap, resident, kv, scratch, per_token, open_budget, current_budget) → PressurePlan`** — pure arithmetic, no OS calls, nothing faked. It re-runs the open-time sizing on a fresh sample: the reserve (resident set + KV allowance + scratch + OS headroom of ⅕ total) is **re-charged in full on every call**, so pressure can never eat the memory the resident set and KV live in. Pressured budget = min(hard cap if set, free-now − reserve), additionally capped at the open-time budget. Decision: **REFUSE** (target 0, `below_floor` set) when the pressured budget is strictly below the floor; **SHRINK** / **REGROW** / **CONTINUE** by comparison with the current budget.
- **Host contract (documented in code, binding on the session host):** the host samples free memory itself, **at most once per token boundary, never mid-token** — in-flight experts are pinned for a token's duration and no pin spans a boundary by construction of the session loop. SHRINK/REGROW apply through `ExpertCache.resize_budget` (pins held; a pinned overage is returned visibly, never forced). REFUSE applies through `shed_to_resident(0)` — deliberately **not** `resize_budget`, whose contract refuses a non-positive budget (unit-pinned below) — observes any pinned remainder the shed returns, then stops the run cleanly stating the plan's numbers.
- **Unit tests (PROVEN, VM, lightest target** — `mojo run -I aesir_engine aesir_engine/tests/test_expert_cache.mojo`, the J-018 recipe; VM MemAvailable ≈ 2.5 GB, no inference): **9/9 groups PASS** — the 7 pre-existing plus two new J-028 groups: *pressure decisions* (shrink arithmetic on the sizing test's stated machine — reserve 2,600 re-charged, open 7,400 → shrink target 3,400 at free 6,000; at-floor-exactly continues at 1,000; below-floor refuses with target 0; negative raw clamps to 0 and refuses; regrow capped at the open budget at free 50,000 and at the hard cap 4,096 where set) and *pressure drive* (a real fsketch cache shrunk 800 → 200 with a pin held: the pinned expert survives, the coldest shed first, resident exactly 200; refusal shed leaves exactly the pinned 100 bytes visible, then 0 once unpinned, entries 0; regrow restores the cap to 800 while resident stays 200 — shed entries are not resurrected — and the regrown cache admits on demand again; accounting closes).

**Verdict rule (pre-registered, §2 of the simulator's header states the same text).** The slice passes iff **all** hold: **(a)** after every pressure event resident ≤ new budget, except explicitly-reported pinned overage (the trace simulator holds no pins, so its allowed overage is 0); **(b)** every non-refusal schedule completes the full trace with accounting closing (hits + misses = accesses = 73,856; admissions − evictions = entries at every token end); **(c)** the below-floor schedule refuses at the stated token (288), sheds to zero resident bytes *before* refusing, serves exactly the tokens before it, and never resizes to a non-positive budget; **(d)** degradation vs the no-pressure baseline is reported in full for every schedule, whatever it is — no threshold is set on it; the honesty is the requirement.

**Schedules** (budgets in pairs; open 512, the J-024 operating point; floor 128 pairs = one token's full routed demand — 8 experts × 16 layers, exact in pairs by the trace's construction and asserted in the simulator from the header's per-layer sizes; events apply *before* the named token): **BASE** (no events); **STEP** (512 → 256 at token 192 → 128, the floor itself, at 384); **CRASH** (512 → 64, half the floor, at token 288 → refusal); **RECOVERY** (512 → 256 at 144 → 128 at 288 → regrow to 512 at 360); **SQUEEZE** (gradual: −32 pairs every 48 tokens, 480 → 160, never reaching the floor). The **no-shed counterfactual** is reported per schedule as the swap-risk quantity: what the unpressured run's resident trajectory would have held against the pressured allowance (max excess bytes; tokens over allowance) — SIMULATED by construction and named as such wherever quoted.

## 4. Measurement (offline, on the real J-016 trace)

Budgets in pairs × mean scaled pair size 3,720 (full-scale bytes = scaled × 1,024), exactly as J-016/J-018/J-024 built them. Trace scope limit as ever: one model (OLMoE), one quant, prompt-phase (577 tokens).

|---|---:|---:|---:|---:|---:|
| BASE (512 throughout) | 0.769 | 65.19 GB | 113.0 | — | 1.000 |
| STEP (→256 @192, →128 @384) | 0.545 | 127.97 GB | 221.8 | −0.223 | 1.963 |
| SQUEEZE (512→160 gradual) | 0.603 | 111.81 GB | 193.8 | −0.166 | 1.715 |

\* CRASH's row covers only the 288 tokens served (36,864 accesses), all of them at the unpressured 512 budget — its hit rate is the *unpressured first half's*, not a pressure benefit, and it is not comparable to the full-trace rows. It is filed so the refusal's accounting is complete, not as a degradation figure.

**Rule (a) — the invariant held everywhere:** 0 violations in every schedule; after each event the resident bytes equal or sit under the new budget (STEP: 951,264 then 475,632 scaled against budgets 952,320 / 476,160; SQUEEZE sheds at all 11 steps, resident tracking each new cap). **Rule (b):** accounting closed at every token end in every non-refusal schedule (0 violations; all four complete 73,856 accesses). **Rule (d) — the degradation, stated plainly:** pressure is expensive on this workload, in the shape J-016/J-017 predicted (no hot set; a smaller cache streams more, roughly in proportion). Holding the floor for the last 193 tokens (STEP) costs a fifth of the hit rate and nearly doubles streamed bytes; even the gentlest squeeze (−32 pairs per 48 tokens to 160) costs −16.6 hit points and 1.72× streamed. RECOVERY shows the asymmetry regrow cannot undo: after 72 tokens at the floor, restoring the 512 cap at token 360 does not restore the working set — the run ends at hit 0.658, having re-streamed what the sheds evicted (evictions 1,858 vs base 1,668; evicted-before-reuse 19,873 vs 12,194). That is the honest price of shedding, and it is the price of *not* swapping the machine.

**The swap-risk counterfactual (SIMULATED):** had the cache refused to shed, its resident bytes would have exceeded the pressured allowance by up to **1,462,763,520 B** under STEP (385 tokens over allowance) and RECOVERY (216 tokens), **1,340,866,560 B** under SQUEEZE (529 tokens), and **1,706,016,768 B** at CRASH's refusal point. Those excess bytes are precisely the memory the machine no longer had — the quantity that becomes swap traffic or an OOM in a system that defends its cache. They are a simulated trajectory difference, not a measured swap figure; no swap was induced or observed anywhere in this slice.

## 5. Refusal behaviour (rule (c) — PASS, exactly as pre-registered)

CRASH's event at token 288 (pressured budget 64 pairs, half the floor) produces: decision REFUSE; the cache sheds **before** refusing — resident 1,903,584 scaled bytes (≈1.949 GB full-scale, 512-pair working set) → **0 bytes, 0 entries**; the run serves exactly 288 tokens / 36,864 accesses and no token after; no resize to a non-positive budget occurs anywhere in the protocol (the refusal path is `shed_to_resident(0)`, and the unit tests pin that `resize_budget(0)` raises). The refusal is clean in the sense the roadmap demands: the run stops by its own stated rule, with its memory already returned, its accounting closed (hits + misses = accesses over the served prefix), and its reason — pressured budget 64 pairs < floor 128 pairs — carried in the plan itself. What a refused run does *not* do: degrade silently at a sub-floor budget, hold its working set while the machine swaps, or touch resident/KV bytes (the reserve protecting them was re-charged in the very computation that refused).

## 6. Verdict

- **The pressure policy is built in the engine** — `plan_pressure_budget` + the token-boundary host contract in `expert_cache.mojo`, the contract restated on `moe_session.mojo` — **PROVEN** at the cache layer (9/9 unit groups, §2; gate + real-module replay, §3).
- **The pre-registered rules all pass** on the measured trace: invariant (a), accounting (b), refusal (c), reported degradation (d). The behaviour the roadmap names exists and is measured: shed under pressure, continue at the floor, regrow capped, refuse cleanly below the floor.
- **The cost is on the record:** shedding is not free (−11.0…−22.3 hit points and 1.48–1.96× streamed bytes across the continuing schedules) and regrow does not refund it. No tok/s or wall claim is made anywhere in this slice.
