## 3. What "text generating on the chip" implies for a prompt graph — and what it does not

The finish-line campaign's completion criterion, as the shared record states it, is **text generating on the chip itself** — the parked campaign completes when a model produces text with the generation computed on the Hailo-10H, evidenced by its own runs. This brief takes that criterion exactly as that campaign's: it does not redefine it, grade it, or set its bar. What this brief *does* — its actual subject — is state what that proof, once filed, would and would not establish **for a prompt graph specifically**, because J-063's subject is not generation.

**What text-on-chip proof DOES establish** (for the silicon and toolchain it names):

- The chip is reachable and programmable end-to-end: a compiled graph of *some* shape was built by the named toolchain, loaded, executed on the silicon, and its outputs returned to the host. The vendor/compiler road is therefore real, on that host, at those versions (G2).
- A session/executor path of *some* form exists on that campaign — enough to run the generation shape it ran.
- The machine discipline around the chip (host, driver, power, thermals at generation load) held for those runs, to whatever extent that campaign's filings record it.

**What it does NOT establish — the prompt-graph gap.** A prompt pass is not generation, in four concrete ways, each of which is a fact a prompt leg needs that a generation proof does not contain:

1. **Shape.** Generation steps are one-token (reply-shaped) computations, repeated. A prompt pass reads a *block* — J-061's design reads at the host's chunk discipline (cap 256) with a floor of 64 tokens (the census's documented NPU floor). A graph compiled for a one-token step says nothing about whether a block-shaped graph compiles, fits, or executes: different tensor shapes, different intermediate sizes, possibly different compiler behaviour entirely. The census's own NPU ground makes the same distinction from the other side: its NPU takes *prompt blocks* as its one documented job and never takes a reply token at all.
2. **Compilation.** J-061's preparation is *one compiled graph per NPU layer* for the prompt form. A generation proof compiles whatever its shape needs; the prompt form's per-layer block graphs are separate compilation artefacts whose success, time, and cache behaviour are unproven by any generation run.
3. **Transfers and returned tensors.** A prompt graph's host↔chip traffic is block-shaped: the block's inputs go up, and the per-layer outputs (hidden states / KV contributions, per J-061 §3's execution shape) come back, once per block. Generation traffic is token-shaped. Transfer correctness at block shape — sizes, layouts, the join with host-computed state — is a prompt leg's own evidence.
4. **Preparation.** J-061's one-time preparation (8-bit copies + per-layer graph compilation, progress on the status line, graph-cache behaviour) must *complete* for the prompt form before any prompt token is read. A generation campaign's preparation, if any, prepares different artefacts; the prompt form's preparation completing — cold and cached — is its own filed fact (start item S4), and its *time* is a measured quantity no gate supplies (§9).

**The consequence, stated as the brief's central ruling:** for *this* road, text-on-chip (G3) is **necessary and not sufficient**. The gate additionally requires **G4, prompt-graph evidence**: at least one compiled prompt-shaped graph — a multi-token block read, at or above the 64-token floor, for at least one layer of at least one named model — actually executing on the chip named in G2, with (i) the graph's compilation record filed, (ii) the host↔chip transfers for that execution stated (what went up, what came back, in what layout), (iii) the output tensors returned to the host and filed or checksummed so a later hand can see they are real outputs and not a success flag, and (iv) the preparation that produced that graph shown completing. G4 is deliberately the *smallest* prompt-shaped proof: one graph, one block, one layer suffices to open the gate. Grading that output's *faithfulness* is not G4's job — it is J-063's, through J-060's battery (§5, S5). G4 establishes that a prompt graph *runs*; nothing in it claims the run is fast or faithful (§9).
