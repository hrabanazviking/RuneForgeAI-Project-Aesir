## 1. Verdict — and the rule, pre-registered before any seeded run

**J-082 closes CLOSED-WITH-DEFERRED-LEG:** the sampled form of J-071's invariant now exists as a built, tested layer. Where J-071/J-072 proved the greedy machinery can never change the text, this slice proves the sampling machinery can never change the *distribution*: under temperature / top-k / top-p shaping, the speculative sampler's seeded output frequencies match the shaped **target** distribution within chi-square tolerance in every registered case, and the uncorrected control fails the same test in every case — the test is proven able to fail, so its passes mean something. The live leg (a real model pair sampling live) is **DEFERRED-WITH-REASON** (§6) behind the road's two global blockers, with its exact recipe re-cited for the J-086 gate.

**The verdict rule (pre-registered; the module header of `core/speculative_sampling.mojo` is its normative text, written before any seeded run was executed):**

- **Fixtures (vocab V = 8, stated logits, Float64):** target logits `[2.0, 1.0, 0.5, 0.0, -0.5, -1.0, -1.5, -2.0]`; draft logits `[1.2, 0.2, 1.6, -0.8, 0.6, -1.4, -0.2, -2.2]` — deliberately different from the target (per-token acceptance Σ min(p, q) between 0.467 and 0.594 across the cases, so the acceptance path and the residual path both carry real mass everywhere).
- **Cases (shaping applied to BOTH distributions with the same parameters; the correction always consumes the SHAPED p and q):** A: temperature 1.0, no truncation. B: temperature 0.7. C: top-k 3. D: top-p 0.8. E: temperature 1.4 + top-k 4 + top-p 0.9 combined.
- **Runs:** N = 60,000 single-position speculative samples per case, primary seed 20261101 — one `core/sampler.mojo` RuneRNG stream per case, three draws per step (draft, acceptance, residual) consumed in fixed order whether or not the step needs them, so the stream is a function of (seed, case) alone. (A second seed, 777, was run in the design prototype as a robustness witness: corrected PASS / naive FAIL in all five cases there too; the Mojo verdict rests on the primary seed alone, as registered.)
- **Statistic:** Pearson chi-square of observed counts against the SHAPED TARGET distribution, df = (target support size − 1), graded at α = 0.001 (critical values: df 2: 13.816, df 3: 16.266, df 7: 24.322). The corrected sampler must PASS (statistic < critical) in **every** case. An observed count in a bin where the shaped target has probability zero is an automatic FAIL (the statistic is infinite there); the module reports that state as the sentinel −1.0, never as a small number.
- **The control:** the NAIVE sampler — emit the draft token unconditionally, no correction — over the same fixtures, the same N, the same seed, must FAIL the same chi-square in **every** case (statistic > critical, or the automatic zero-bin FAIL in the truncated cases, where the draft's shaped support reaches tokens the target truncated away). A slice whose control passes has proved nothing and does not bank.
- **Bonus path:** rounds of k = 2 over case A's stationary fixture (the same shaped p and q at every position), seed 424242, run until 12,000 bonus tokens are collected (rounds capped at 200,000; the collection count is filed). Bonus tokens — emitted only on full acceptance, drawn from p by the rule — must PASS the same chi-square against p at df 7.
- **Deterministic legs (no statistics):** scripted-draw rounds pin the mechanics exactly — acceptance prefix, residual emission on the rejecting position and nowhere else, bonus emission on full acceptance and nowhere else, and every refusal (k outside the J-071 band 1..15, flat-length mismatches, malformed distributions, out-of-range draws, the undefined residual of identical distributions).

**The rule being graded** (standard speculative sampling): per position, draw the draft token x from the shaped draft distribution q; accept x with probability min(1, p(x)/q(x)); on rejection emit a draw from the residual distribution norm(max(0, p − q)) and end the round; if all k positions accept, emit one bonus token drawn from the target distribution at position k. The emitted token at every position is then distributed exactly as p — the acceptance path contributes min(p, q), the rejection path contributes p − min(p, q) — an exact identity, not an approximation.

## 2. What was built, and where it binds (PROVEN, VM, lightest target)

- **`aesir_engine/core/speculative_sampling.mojo` (new)** — the pure correction layer: `shape_distribution()` (logits → shaped distribution), `acceptance_probability()` (min(1, p/q)), `residual_distribution()` (norm(max(0, p − q))), `draw_from_distribution()` (inverse-CDF over explicit draws), `sample_position()` (one position of the rule), `run_sampled_round()` (k positions + correction-or-bonus, over per-position shaped distributions in flat form), and the grading helpers `chi_square_statistic()` / `chi_square_critical_001()` / `support_df()`. It binds, and duplicates nothing:
  - **Shaping ← the engine's own sampler:** `shape_distribution()` applies, in `core/sampler.mojo`'s own order (temperature, softmax, top-k, top-p, renormalising after each truncation — the sampler renormalises implicitly by softmaxing over the kept candidates, the same arithmetic on the kept support), and the seeded runs draw from the sampler's own `RuneRNG`. Stated differences, so no reader believes the paths byte-equal (§7): the sampler's greedy branch returns the argmax before shaping, mirrored here as temperature 0 → the one-hot distribution at the argmax (lowest id on ties, the sampler's tie rule); the sampler pre-filters candidates to logits within 15.0 of the max (relative probability < e^−15 ≈ 3×10⁻⁷), a full-vocab numerical guard immaterial here; the sampler works in Float32 over f16 logits, this layer in Float64 over stated fixtures — the precision the distribution evidence is graded in. Repetition/frequency/presence penalties and min-p are context-dependent logit edits the host applies BEFORE shaping (exactly where the sampler applies them, before temperature); they are out of this slice's scope by name.
  - **Acceptance arithmetic ← `core/speculative.mojo`:** `acceptance_probability()` is the same min(1, p/q) the legacy `SpeculativeEngine.evaluate_acceptance` applies, restated over shaped distributions with its own validation (a drafted token's q must lie in (0, 1] — a token the draft cannot propose has no acceptance question). The legacy engine's `verify_and_reconcile` refusal named exactly what was missing — "per-step normalized distributions, residual sampling, and KV coordination" — and this module supplies the first two as a pure layer; the third (KV coordination) belongs to a live host and stays refused there (§7).
  - **Round shapes ← J-071/J-072:** k is bound to the same band (1..15, pass width k+1 in 2..16); a sampled round emits accepted + 1 tokens exactly as a greedy round does, so J-072's rollback arithmetic (commit snapshot + emitted count) carries over unchanged; the host contract in the module header states the one difference a sampled host must honour — a sampled round consumes RNG draws (k draft + k acceptance + 1 final under this module's fixed consumption), where J-071's zero-draw invariant binds greedy rounds only.
  - **No gate lifted, no session wired:** `require_draft_check_use()` (J-036) still fails closed and the facade's `speculative_generate` still raises not-implemented (both re-verified by the inspection recount, §5). Wiring a correction layer into a session with no proposer and no verify executor would fake an integration that cannot run (the J-072…J-081 precedent). The suite is not registered in `run_all` (the J-031 precedent: registration rides with the counted run the VM's memory gate does not permit).
- **`aesir_engine/tests/test_speculative_sampling.mojo` (new suite, 17 groups)** — §5. Its fixtures are the registered stated logits, never a model's.
- **`docs/janas/j082_mirror.py` (new)** — an independent Python replica of the registered runs (same RuneRNG arithmetic, same fixed draw consumption, same shaping), filed so the Mojo statistics can be checked against a second implementation (§3).

## 3. The chi-square evidence (the slice's result)

Every number below is from the filed Mojo run (`j082_test_output.txt`), graded against §1's pre-registered rule. The Python mirror (`j082_mirror_output.txt`) reproduces **every statistic to six decimal places** — two independent implementations of the rule, the RNG, and the shaping agree exactly, so no filed number rests on one code path's say-so.

| Case | Shaping (both models) | df | Corrected χ² | Critical (α=0.001) | Verdict | Naive control χ² | Control verdict |
|---|---|---|---|---|---|---|---|
| A | T=1.0, no truncation | 7 | **8.518** | 24.322 | PASS | 69,594.87 | FAIL (as required) |
| B | T=0.7 | 7 | **5.676** | 24.322 | PASS | 183,613.44 | FAIL (as required) |
| C | top-k 3 | 2 | **0.641** | 13.816 | PASS | zero-bin (−1.0 sentinel) | FAIL (as required) |
| D | top-p 0.8 | 2 | **1.675** | 13.816 | PASS | zero-bin (−1.0 sentinel) | FAIL (as required) |
| E | T=1.4 + top-k 4 + top-p 0.9 | 3 | **5.597** | 16.266 | PASS | zero-bin (−1.0 sentinel) | FAIL (as required) |
| Bonus | case A fixture, k=2 rounds | 7 | **6.747** | 24.322 | PASS | — | — |

Bonus collection: 12,000 bonus tokens from **34,835 rounds** (seed 424242) — a full-acceptance rate of 0.344 against the fixture's registered per-token acceptance 0.589 (0.589² ≈ 0.347 expected; the collection is consistent with the fixture, and no acceptance-rate claim about any model is made from it — §4).

Reading the control honestly: in cases A and B the naive sampler's failure is a finite, enormous statistic (it emits the draft's distribution, which is visibly not the target's). In the truncated cases C–E the failure is structural — the draft's shaped support includes tokens the target truncated to probability zero (case C: draft support {0, 2, 4} against target {0, 1, 2}), so the naive sampler emits impossible tokens at a ~18% rate and the statistic is infinite by construction. Both failure shapes are the point: an uncorrected sampler does not merely drift from the target under shaping, it emits tokens the shaped target forbids.

The shaped distributions themselves are pinned exactly in the suite (§5) against hand-computed values — e.g. case C target `[0.628532, 0.231224, 0.140244, 0, 0, 0, 0, 0]`, draft `[0.328879, 0, 0.490629, 0, 0.180492, 0, 0, 0]` — so the chi-square grades the correction against distributions that are themselves verified, not against whatever the shaping code happened to produce.

## 4. What this settles, and what it does not

- J-071's invariant is now proved in both forms the road states: greedy speculative output is token-identical to plain greedy (J-071/J-072, by construction), and sampled speculative output is distribution-identical to plain sampling from the shaped target (this slice, by seeded chi-square with a failing control). Together they are the honesty spine the J-086 gate re-runs.
- The correction provably consumes the SHAPED distributions: cases C–E cannot pass against unshaped distributions (the supports differ), and the naive control's zero-bin failures are precisely the failure a host would ship if it corrected against the raw softmax while sampling from the shaped one, or skipped the correction under shaping. The host contract (module header) states the obligation in those terms.
- Nothing here grades a real model pair. The fixtures' acceptance sums (0.467–0.594) are fixture properties chosen so both paths carry mass; they are **not** acceptance rates for any pair, and no speed, tok/s, or quality claim exists anywhere in this slice. A live pair's distributions are whatever its logits shape to — the layer's honesty over them is §6's leg, graded by the same rule shape.

## 7. Answered-locally / defect record / exclusions (clean-room)

- No Janas material was consulted; every design question was answered from Aesir's own architecture and the road's filed records, and is recorded here as answered-locally: (a) **the shaping binding** — the sampler's order and renormalisation semantics are adopted verbatim in substance (§2), with its three stated deltas (greedy one-hot form, the 15.0 pre-filter, Float64 vs Float32) recorded rather than smoothed over, because the chi-square grades distributions and a silent second shaping semantics would make the evidence ambiguous; (b) **fixed draw consumption** (three draws per position, one final draw per round, whether or not the path needs them) — chosen over lazy consumption so a seeded stream is a function of (seed, case) alone and the Python mirror can reproduce the Mojo statistics bit-for-bit in count terms, which it does (§3); the design prototype's lazy-consumption witness (seed 777) is filed as a verdict witness only, for the same reason; (c) **the identical-distribution residual is refused, not defaulted** — when p == q the rejection path is unreachable (acceptance is 1 almost surely), so a caller asking for the residual has a bug, and the honest response is a refusal that finds it; (d) **the zero-bin statistic is a sentinel, not a number** — reporting infinity through a Float64 would let a careless reader sort it as "large but finite"; the −1.0 sentinel with its named constant cannot be misread as a passing small statistic, and the suite asserts the control's truncated-case failures through it explicitly; (e) **the legacy `SpeculativeEngine` is not edited** — its `verify_and_reconcile` also names KV coordination, which no pure layer can supply; the engine's refusal therefore stands until a live host exists, and this slice's layer is additive beside it (the J-081 precedent: build the missing pure layer, lift no gate).
- **Defect record:** no defect was found in prior work — the three neighbour suites reproduce from this tree (§5), J-071's header already named this slice's account correctly, and `core/speculative.mojo`'s acceptance arithmetic and refusals are exactly as J-071/J-072 recorded them. No defect was found in this slice's own work either: the module and suite passed 17/17 on their first filed run, the deterministic expectations were hand-derived before compiling, and the independent mirror reproduces every statistic. One record correction is stated for the avoidance of doubt: the design prototype's per-case statistics (lazy draw consumption) differ numerically from the filed Mojo statistics (fixed consumption) — both streams are seeded and honest, the verdicts agree in all five cases under both, and only the Mojo numbers are filed as this slice's evidence.
