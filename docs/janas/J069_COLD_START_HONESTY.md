**The cold-start shape (pre-registered).** A session's life has two regimes:

- **COLD — the first prompt after open.** Its wall is a sum of four components, each reported separately or stated not-applicable with its reason:
  - **C1 OPEN** — process start → model open complete (file open, mapping, directory parse, resident-set load).
  - **C2 COMPILE** — first-use compilation/initialisation on the execution path (CUDA context + first kernel use, graph compilation where a backend compiles, first-touch allocation). A surface with no compilation step states 0 with that reason; an unmeasured compile cost is never folded silently into the first prefill.
  - **C3 PREP** — one-time preparation (J-061's NPU preparation: 8-bit copies + graphs — a graph-cache hit is a *different* C3 figure from a cold prep, never an average of the two; expert-cache sizing; open-time autotuning). Not-applicable is stated, never omitted.
  - **C4 COLD PREFILL** — the first prompt's own prefill with cold caches: the expert cache opens empty (J-017 §5.2 — token 0 can owe the full 487,587,840 B cold ceiling on OLMoE; J-020 measured token 0 at exactly that, vs 130,056,192 B warm), the page cache in its stated state (J-019's discipline: cold is *measured* — DONTNEED + mincore — never hoped), the prefix cache empty.
  - The cold total is exactly C1+C2+C3+C4. A single merged "first prompt" number with no component split is not a cold figure this road may publish.
- **WARM — any prompt after the first**, in a session whose open, compile, and prep are done, caches in their stated state. A warm figure excludes C1, C2, and C3 entirely, and a warm median over repetitions excludes the first (cold) repetition.

**The verdict rule (pre-registered, implemented as `evaluate_cold_claim`).**

- **PERMITTED by accounting alone:** the separation claim itself — a report states all four cold components separately (or not-applicable with reason) and keeps warm figures free of C1–C3.
- **REQUIRES LIVE:** any cold wall, warm wall, or tok/s figure, however classified. Accounting classifies and separates; it contains no speed.
- **REFUSED outright:** a warm claim grounded on a cold-first run; a warm claim whose figure includes open/compile/prep time (conflated); a cold claim grounded on a warm or conflated run; a merged cold total with no component split; a warm median that contains the cold repetition.

## 3. Design — the account

**`aesir_engine/core/cold_start_account.mojo`** (new, pure arithmetic in the J-066/J-067/J-068 pattern; executes nothing, times nothing, contains no speed):

- **`ColdStartAccount` / `plan_cold_start(...)`** — one cold first prompt in four components (open_ms, compile_ms, prep_ms, cold_prefill_ms) with its state flags (`prep_applies`, `prep_cache_hit`, `expert_cache_cold`, `page_cache_cold`); `overhead_ms()` = C1+C2+C3, `total_ms()` = the exact sum, `overhead_share_bp(...)` the overhead's share in basis points. Refusals: any negative component; a prep figure for a preparation that does not apply (must be 0 — a nonzero figure means a different surface's prep was priced); a graph-cache hit without a preparation; a cold prefill claimed against a warm expert cache (a first prompt that found its experts resident is a different case — e.g. prefix reuse — and must be restated, not filed as cold).
- **`classify_run(...)`** — COLD_FIRST iff first prompt after open facing an empty expert cache; WARM iff not the first prompt and the figure includes none of open/compile/prep; CONFLATED otherwise (a later prompt still carrying an open-time component, or a claimed first prompt whose cache was not empty). A conflated run grounds neither a cold nor a warm claim until restated.
- **`repetition_verdict(...)`** — REP_OK (≥2 repetitions, first filed separately as cold; warm medians over repetitions 2..n only); REP_SINGLE_COLD_ONLY (one repetition *is* the cold run — no warm figure may be derived); REP_REFUSED_MIXED (≥2 repetitions with the first folded into the median).
- **`evaluate_cold_claim(...)`** — the §1 rule on every branch (separation / cold-wall / warm-wall × permitted / requires-live / refused), in the J-067 claim-verdict vocabulary, with `run_class_name` / `claim_name` / `repetition_verdict_name` exact-name helpers.

**Host contract** (in the module header, binding): the host records C1–C3 as it performs them at open (0 with reason where a step does not apply; `prep_cache_hit` stated for C3); the first prompt's prefill is recorded as C4 with its cache states; every later prompt is warm by classification; repetition plans file repetition 1 separately; every published wall/tok/s passes `evaluate_cold_claim` first. **No existing module was modified** — wiring a live surface to report through this account rides with the first live leg under §7 (the J-067/J-068 pattern: the account is the contract a post-gate open follows).
