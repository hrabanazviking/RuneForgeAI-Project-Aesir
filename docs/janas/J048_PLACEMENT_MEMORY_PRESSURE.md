## 1. Question and ground

**Question.** Part II's expert cache and Part III's placements were each sized against memory as if they owned it: J-028's pressure planner re-charges a reserve (resident set + KV + scratch + OS headroom) so mid-run pressure never eats the memory the resident set and KV live in, and J-031's GPU division charges a device pool resident-first, KV/activation/reserve next, the remainder as a device expert cache. But neither slice states the rule for the pools where the two genuinely compete for the *same* bytes: a device's VRAM holding both a placed resident set and a device expert cache; a unified/host pool holding both a placed pass's fixed bytes and the host expert cache; and a device *copy* of cached bytes — the shape in which Janas's documentation says its NPU stays closed where the expert cache cannot hold the feed-forward weights, because its 8-bit copies' memory is the cache's memory (census contention-closure row, filed from Janas's public documentation). When the pool shrinks — at open, or mid-run — who yields, in what order, down to what floor, and what happens at the floor?

**Ground, and only that ground.** J-028's planner and host contract (`plan_pressure_budget` in `core/expert_cache.mojo`: cache sheds first, policy-ordered; resident/KV never cannibalised; regrow capped at the open budget; below the floor — one token's full routed demand — shed to zero and refuse cleanly; re-plans at token boundaries only). J-031's division accounting (`core/moe_gpu_plan.mojo`: resident first, allowances next, remainder as whole-expert device cache; below one largest whole expert the division is resident-only; fixed over budget is the CPU line, stated). J-017's residency budgets and the atomic whole-expert unit. J-037's inventory truth. The Part III choosers' session-keeping (J-040–J-042: a choice is decided once and kept). J-044/J-045's learned/re-trial surfaces (placement changes are open-time or re-trial decisions). J-047's supremacy stack and whole-refusal shape. The census's one contention fact (the NPU-closure row above) is a *pattern to answer*, not a rule to copy: the roadmap requires Aesir's rule to come from Aesir's numbers. No Janas source was opened; none was needed. Questions the ground does not answer are answered locally in §6.

## 2. The contention rule — DECIDED, stated before measuring

For one contested pool (one plan per pool; a session with a host pool and a device pool plans each separately):

1. **Fixed first.** The governing placement's fixed bytes — resident set + KV allowance + activation/scratch + the pool reserve, in J-031's/J-028's charging order — are charged in full, first, at open and at every re-plan. The cache never cannibalises them; they are never shed to feed the cache.
2. **Cache elastic.** The expert cache is the pool's only elastic consumer: budget = min(open-time budget, expert body where a body bounds it, pool − fixed − admitted copies). It sheds first under pressure (J-028's order and cadence are the host's mechanics) and regrows only toward the open-time budget.
3. **Duplicate copies are cache-class, unless a hand names them.** A copy duplicating bytes the cache/host already holds (the NPU-copy shape) is admitted only if the cache still holds at least the floor after charging it; otherwise the copy stays **closed** and the cache keeps its budget — closing a copy loses an accelerator copy, never the weights, because the originals remain. This is Aesir's derivation of the census's closure pattern, from Aesir's own floor (§5 prices why the floor, and no higher line, is the threshold — §6).
4. **Degrade before refuse, where a fallback exists.** Below the threshold (the floor; for an optional cache, the larger of the floor and one largest whole expert): an **optional** cache — a device expert cache whose experts still live in the host cache — degrades to zero and the placement stands (experts compute where they land on the host; J-031's resident-only division). A **required** cache — the host cache a streamed session has no fallback without — refuses cleanly (J-028's REFUSE: shed to zero, stop, state the numbers).
5. **Manual supremacy is never traded away (J-047).** A governing hand choice is never shrunk, migrated, substituted, or trimmed to cure contention, and a copy a hand choice names charges as fixed (rule 3's exception). If fixed bytes alone exceed the pool, or a hand placement leaves a required cache below its floor, the plan is REFUSE — the whole session refuses at open with the numbers stated. That is J-047's whole-refusal shape, not an override: `choice_overridden` is False on every plan the planner can return, and the suite pins it.
6. **Placement never migrates mid-run.** A re-plan (token boundaries only, J-028's cadence; never mid-token) may change only the cache budget and a copy's admitted state. Moving a placement is an open-time or next-session (learned / re-trial) decision, because the choosers' choices are session-kept by design.

## 5. Measurement — the price of the rule (SIMULATED on MEASURED inputs)

**Validation gate — PROVEN.** Before any sweep number was trusted, `j048_contention.py` reproduced, **EXACTLY** from the campaign copies of the prior results files: J-024's fsketch global counters at 128/256/512/1,024 pairs (hits 25,953 / 39,394 / 56,781 / 72,832 and streamed bytes, every cell checked) and J-028's schedule record (base hits 56,781, step hits 40,277, CRASH refusal at token 288 with pressured 64 pairs against the 128-pair floor). **Sweep (the planner over filed OLMoE inputs; cache-quality figures are the filed fsketch counters at the same pair budget — the simulation's stated assumption, since a device cache's own hit behaviour is not measured):**

| Cache the pool leaves | Device pool (optional) | Host pool (required) | Filed hit rate | Filed streamed MB/token |
|---|---|---|---:|---:|
| 1,024 pairs (whole body) | FULL | FULL | 0.986 | 6.76 |
| 512 pairs | SHRUNK | SHRUNK | 0.769 | 112.98 |
| 256 pairs | SHRUNK | SHRUNK | 0.533 | 227.62 |
| 128 pairs (the floor) | SHRUNK | SHRUNK | 0.351 | 316.16 |
| 64 pairs (below floor) | **NO_CACHE, placement stands** | **REFUSE** | — | — |

**What the numbers decide.** (a) Contention is expensive in exactly the shape J-016/J-017 predicted (no hot set): taking the cache from 512 to 256 pairs to make room costs −23.6 hit points and 2.01× the streamed bytes; 512 → 128 costs −41.7 points and 2.80×. Fixed-first is therefore not a free ordering — it is chosen because the alternative (shedding a placed resident set or a KV cache mid-run) has no honest mechanics in the tree at all, while cache shedding has J-028's proven ones; the price is filed, not hidden. (b) The stated J-031 machine never contends: FULL with 804,657,152 B headroom — contention on this road's measured model begins only on smaller pools or bigger bodies (the J-032 class), which is why the rule is proven as planning arithmetic plus trace-priced simulation, and its live leg belongs to the gate (§7). (c) The degrade/refuse split at 64 pairs is the rule's sharpest consequence, and it is asymmetric on purpose: the device cache has a fallback (the host cache) and the host cache does not.

**Auto-copy scenario (SIMULATED, scenario input stated):** a duplicate copy sized at 256 pairs of bytes (975,175,680 B — a stated scenario in measured units, not a measured copy size; no NPU copy size is filed on this road and none is invented) closes exactly at the floor line (pool leaving floor−1 after the copy → copy closed, cache keeps 1,462,763,519 B) and is admitted where the cache keeps the floor exactly (cache = 487,587,840 B). The closure boundary is the floor itself, byte-exact in both the Python mirror and the Mojo suite (group 7, at a 200,000,000 B copy).

## 6. Answered-locally records (clean-room)

- **Q: At what cache size should an auto duplicate copy close — the floor, or a higher line?** The census records only that Janas closes its NPU in this case; it states no threshold Aesir may take. Answered locally: **the floor**, because the floor is already Aesir's decided, measured minimum working set (J-028: at exactly the floor the run continues, barely, by definition; J-024/J-028 price life at the floor rather than declaring it unusable). A higher, second threshold would contradict J-028's boundary and invent a number no measurement supports. The cost of floor-level operation is on the record (§5) for any future slice that wants to re-open the question with new evidence.
- **Q: Should contention ever move a placement mid-run instead of shedding the cache?** Answered locally: no (rule 6). The choosers' session-keeping (J-040–J-042) and the re-trial cadence (J-045) already define when placements change; a mid-run migration would need device executors and state transfer that do not exist in the tree, and would silently break the kept-choice contract. Shedding and, at the limit, clean refusal are the honest mechanics that exist.
- **Q: Is the NPU a special case in the planner?** No. The planner knows only *duplicate copies* and whether a hand named them; the parked Hailo is never probed, its branch never touched, and any NPU-specific application of this rule (roadmap J-065, conditional on the finish-line gate) is deferred with that gate (§7). The census's closure pattern is answered in the abstract, as the slice's dispatch required.
- **Q: One plan per session, or per pool?** Answered locally: per pool. Host RAM and device VRAM are separate pools with separate floors and fallbacks (the §5 asymmetry is exactly a per-pool fact); a single cross-pool plan would have to invent an exchange rate between pools that no measurement in the tree supports.
