## 1. Question and ground

**Question.** J-040 built the prompt kind's chooser and J-041 the reply kind's. The draft-check kind — the small-batch verification pass of speculative decoding, token band 2–16 (J-035's taxonomy) — is the band where accelerators are least obvious: the batch is too small to amortise a device launch the way a prompt chunk (up to 256 tokens) does, yet each token's verification work is a full-width forward over the batch, so the parallelisable fraction is larger than reply's width-1 work. How does the engine choose a draft-check placement by measurement, keep it for the session, and report what it chose and why — feeding Part V, which will build the pass itself?

**Ground, and only that ground.** The pass taxonomy is J-035's, including its central finding for this kind: **draft-check does not exist in Aesir** — `core/speculative.mojo` is acceptance arithmetic only, fail-closed, wired to nothing (gap **G1**, owned by Part V J-071/J-072). The option forms, precedence, and drafts legality are J-036's — including its two standing facts for this kind: `--drafts-on` parses, validates, and stores exactly like the others, but `require_draft_check_use()` **raises always**, naming G1 + Part V; and the NPU never takes a draft-check pass (an explicit drafts option naming it is refused at parse, whole). The inventory truth is J-037's. The measurement discipline and candidate honesty are J-038's, including its binding classification for this kind: **a draft-check candidate is UNMEASURABLE-WITH-REASON, always** — the classification order puts the pass's absence *before* inventory truth (the strongest true reason first), so draft candidates are never EXCLUDED and never measured, and **no synthetic proxy is measured in its name**. J-039's thread trials record the same for every rung: the ladder is derived (the counts exist), every rung UNMEASURABLE-WITH-REASON, nothing timed. The chooser pattern, record shape, decision rule, and session keeping are J-040's as adopted by J-041. No Janas source was opened; none was needed — every fact above is Aesir's own tree, and every design question the census does not answer is answered locally in §8.

## 3. The decision rule — pre-registered

**This rule was written into the module header and this section before any J-042 live number existed** (the module and this doc's §3 were authored before the first J-042 test build ran; the filed live record in §6 comes from after — and for this kind the "live number" is in any case the absence of numbers, which §1's ground already guaranteed).

**Adoption, with reasons stated.** The rule is **J-040's rule, adopted unchanged in its numbers for the third kind** — same session default, same 10% margin, same separation hurdle, same decision codes. The reasons are J-041's, unweakened: one rule across kinds keeps choices comparable and keeps the learned file (J-044) one shape; and no draft-check measurement exists that could justify different numbers — inventing a kind-specific margin for the one kind with *no* evidence base would be an unmeasured number dressed as caution. The draft-specific content of this slice lives where it belongs: in the *field's* honesty (§2) and in the fallback's wording (the default is a kept label only — no pass runs anywhere), not in new thresholds.

- **Session default: `cpu threads=1` (serial)** — a kept label only for this kind today: choosing it runs nothing, because no draft-check pass exists to run on any device.
- **Manual first.** A single-device or co-work drafts option **fixes** the choice (decision `MANUAL-FIXED`). The chooser never ranks against it and never substitutes — manual supremacy is J-047's slice; this slice's binding duty is the weaker one: auto never overrides an explicit non-auto option. The named candidate's state rides on the record — for this kind, UNMEASURABLE-WITH-REASON (G1) — and the record states in the open that **choosing is not using**: any actual use of a drafts placement still fails closed through `require_draft_check_use()` (J-036) until Part V builds the pass. A device option does not fix a thread count, and the record says so (for this kind the thread axis is unmeasured in any case). An explicit drafts option naming the NPU never reaches the chooser at all — J-036 refuses it at parse (§5, group 7 pins this).
- **Auto and race rank the measured set** (a race ranks only its named members — group 8). Bound-stopped candidates are recorded and **never ranked**.
- **Zero measured — the only live case today:** the default is chosen as `NO-MEASURED-FALLBACK` when the CPU is present, with every candidate's reason on the record; when the CPU itself is absent the record is a `REFUSAL` — no choice, reasons stated.
- **Exactly one measured:** chosen as `SOLE-MEASURED` — last candidate standing, not a victory; no margin exists and none is claimed. *(Unreachable live today; pinned on injected sets for Part V.)*
- **Two or more:** BEST is a `MEASURED-WIN` only when **both** hurdles clear: **(a) Margin:** (runner − best) exceeds **10%** of best's median; **(b) Separation:** best's slowest counted round is still below runner's median. If either fails, the **default is kept**: `DEFAULT-BY-NOISE` / `DEFAULT-CONFIRMED`, with the failed hurdle stated. *(Unreachable live today; pinned on injected sets for Part V.)*

**Session keeping.** `DraftPlacementSession` decides **once**: `decide_once` stores the first record and refuses a second decision for the same session (the refusal names J-045's re-trial road — group 9 asserts the refusal text carries "J-045"). The report is a stable rendering of the stored record: two reports of one session are byte-identical (group 9). Every report carries the measurability line and the stability line in the open: *no draft-check pass exists today (G1), so no candidate carries a timing and nothing was ranked; this choice rests on no measurement at all — it is the pre-registered fallback for an unmeasurable kind, not a measured verdict.*

## 4. The choice record and report

`DraftChoiceRecord` carries: the resolved drafts option (text + source), the decision code + a decision sentence (with the numbers it rests on, when numbers exist — for this kind today, none do, and `best_median_ns` stays unset, which the live test asserts), the chosen label (or NONE on refusal), **every** candidate as a measurement line (unmeasurable with its verbatim reason; measured/excluded/bound-stopped forms exist for the rule's future inputs), the **axes note** (stating plainly that no timing stands on either axis — or, for manual records, that the trials were not run because the choice is fixed, with every rung's would-be state stated), and the fixed measurability + session + stability lines.
