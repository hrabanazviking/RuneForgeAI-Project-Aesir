## Slice 132 — Document request-to-Hailo connection gap and viable bridge (complete; architecture decision required)

Current path: Æsir request/model selection → local inference/backend dispatch → Hailo command submission → output result is broken at backend selection and device execution. The raw Mojo path has no successful firmware round-trip or executable configuration. The best currently evidenced bridge is a local Hailo GenAI service: Raspberry Pi documents hailo-ollama REST requests; Hailo’s GenAI Model Zoo documents an Ollama-compatible C++ server on HailoRT, while HailoRT documents GenAI LLM APIs. Æsir could remain a Mojo application/orchestrator and use its HTTP boundary to call the local service. In that design, all model inference remains in the supported Hailo runtime on the Hailo-10H; the Pi CPU handles request orchestration only. Æsir must fail closed when the service/model/device is unavailable and must not call its CPU inference backend.

This path is promising but changes the repository’s currently documented no-HEF/no-vendor-runtime/native-engine assumptions: it relies on HailoRT and precompiled Hailo GenAI model artifacts. Official Hailo GenAI docs currently state custom LLM compilation is not available through the documented flow; supported catalog models (for example Qwen2.5 1.5B, Qwen3 1.7B, and Llama 3.2 1B) have published Hailo-10H artifacts and performance rows. Thus the first achievable GO would demonstrate Æsir orchestration over an official Hailo execution backend with an already-supported model, not compile Æsir’s TinyLlama implementation to raw Hailo instructions. A later native-backend effort would need vendor-published raw programming/configuration support that is not currently evidenced.

Compatibility gate: Raspberry Pi’s current official AI setup specifies 64-bit Raspberry Pi OS Trixie, whereas the latest local census records Bookworm. This is an environmental mismatch with the supported install path, not proof of a hardware limitation; do not update the host in this slice. First qualify the supported software stack on an isolated/approved Trixie image or separate compatible host, then use a reversible, evidence-capturing on-device smoke test. No packages were installed and no device was touched.

Decision required before changing the architecture: approve HailoRT plus official precompiled GenAI model artifacts as the inference substrate, with Æsir acting as a fail-closed Mojo client/orchestrator and no CPU LLM route. If that constraint change is not acceptable, the present evidence does not support a technical GO for native no-HEF/no-DFC/no-runtime LLM execution on Hailo-10H.
