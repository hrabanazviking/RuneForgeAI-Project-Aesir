# Original program metadata and lifecycle wire codec

Date: 2026-10-20. Contract: `TASK_hailo10h_program_rpc_codec.md`.
Published source facts: `HAILO10H_PROGRAM_DELIVERY_BOUNDARY.md`.

## Implemented interface

`hailbru/hrpc_program.mojo` constructs owned HrpcFrame values for action-2
create-infer-model metadata and action-3/5/10/11/12 handle-only lifecycle
requests. It parses action-2 handle replies and validates successful empty
lifecycle replies. Existing project protobuf bounds, correlation/status checks
and nested handle construction are reused without changing the device codec.
The diagnostic `smidr/tools/hrpc_program.mojo` only prints/inspects wire values.
It has no device submission consumer.

Declared program size is UInt64, positive and bounded by an explicit caller
host limit. The metadata does not allocate/read/copy that many program bytes.
The separate program transfer still needs an immutable byte owner and exact
length verification. UTF-8 name byte length is checked before body allocation
and the exact final body size before copying name data. Maximum body is the
existing pinned 2048 bytes. Empty strings use proto3 defaults, zero handles
preserve nested-message presence, embedded NUL name bytes are retained, and
the all-ones invalid handle sentinel rejects. The codec does not treat names
as paths or use them in a syscall.

Create replies require a single enclosing handle, with default nested id zero
permitted. Duplicate known fields, wrong known wire types, truncated/overflowed
varints or lengths, invalid handle and reply ID/action/status mismatch reject.
Unknown varint, length-delimited, fixed32 and fixed64 fields are skipped under
the existing bounded reader; unsupported group wire types reject. Lifecycle
actions are explicitly selected; arbitrary action IDs and configure/run bodies
cannot be constructed through this interface. This is a codec boundary,
not a physical-program or model admission rule.

## Remaining physical and compiler work

All diagnostic output reports device_access, program_transferred and
execution_tested false. Creating a wire request neither owns a server handle
nor proves a live endpoint accepts a program. Configure, stream bindings,
program-buffer identity/length, virtual/infer/configured-handle ownership,
bounded transfer deadlines and teardown need future physical acceptance.
No program bytes are sent and no activation/run or model/layer forward occurs.

Continue the active parent `TASK_hailo10h_program_delivery.md` with required
compiled-program metadata/configuration structure and numerical CCW/register
facts. The first numerical operation still requires actual device precision,
placement, original arithmetic configuration, upload/activation and hardware
result/cleanup. The receiver can be a route for Aesir compiler output; it
cannot redefine the owner's goal as vendor-precompiled catalog selection.
